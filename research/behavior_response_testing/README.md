# 行为状态条件化的失效测试

本目录检验一个新的响应先验：用已知历史行为参数训练场景响应函数，测试新目标时以未知行为状态为潜变量，用已查询的连续风险推断它，再预测未测场景失效。目标的真实控制器类型、制动能力、间距与感知延迟不提供给在线选择器。

这次开发使用第一轮未通过后转为开发数据的十六个训练参数组合、每组合两个完整场景池，共 65536 条历史化响应；八个留出开发组合用于前向预测器验证。训练信息包括历史系统的行为配置，和六源冻结 baseline 的原始训练信息不同。后续必须加入使用相同新历史数据、相同预测器的固定排序与离散历史来源适配对照，才能区分新增信息与方法收益。

行为状态由三项物理参数与控制器类型组成，前向模型分别预测连续风险与真实碰撞概率。当前范围是同一仿真器的 IDM/FVDM 参数族；不能从这一设计推出对任意驾驶架构都成立的系统识别。

`model.py` 定义八输入、两输出的条件响应网络；`train.py` 在 GPU 环境 `metadrive` 中直接运行。训练时已知历史参数用于监督；用已知验证参数计算的预测误差只是预测器验证，不能把它当作在线测试方法获得真实目标参数后的公平结果。

待验证的主要机制是：风险反馈能否在连续行为状态中识别影响失效边界的方向，而不局限于六个历史响应的仿射组合。后续比较固定先验排序、离散历史来源后验、连续行为后验，并保持 200 次真实查询；发现速度与最终召回分别验收。当前没有新的独立显著性结论。

五个网络种子已完成训练。`session.py` 使用风险网络均值加场景局部 GP 误差，按查询前的风险预测似然更新行为假设；失效网络概率按行为后验求平均。状态跨两个场景族共享，局部误差按族独立。顺序后验与批量高斯似然、条件均值及跨场景族更新一致；各行为假设失效预测相同时，风险辨识不能改变其失效概率。两项数学检查通过。

八个留出开发组合、两个池、五个网络种子的四方法对照已完成 320 次运行。下表为相对此前六源冻结最佳的配对均值差，单位为百分点；不是独立显著性结果。

| 配置 | 归一化发现面积差 | 最终召回差 |
|---|---:|---:|
| 行为先验固定排序 | −0.18938 | −0.73633 |
| 十六历史状态后验 | +0.36761 | +0.23951 |
| 连续行为后验，512 个粒子 | +0.49870 | +0.20617 |
| 此前最佳算法接入同样的十六来源预测器 | +0.41463 | +0.04640 |

相同信息条件下，连续行为后验相对接入新预测器的此前最佳算法，面积差为 +0.08407 个百分点，召回差为 +0.15978。与离散历史后验相比，连续版本面积较高，召回稍低，因此不能把连续化本身认定为双指标均必要。完整 24 个开发组合的初步 960 次复核已经完成，随后增加误差参数估计及更强 GP 对照，共 1920 次开发比较；训练组合与预测器留出组合分别标记。

此前最佳算法的匹配扩展沿用其 GP 核和选例设置，初始来源为十六个条件模型历史响应、权重均匀，风险到失效的校准用同样十六训练组合重新拟合。原六源冻结输入保持原样。已完成的两种子筛选与五种子留出对照分别保存在 `results/screening_*` 与 `results/held_out_development_*`；当前整体记录在 `results/development_summary.json`。

## 当前候选与完整开发结果

当前候选在 `log_probability.py` 中，使用 512 个连续行为粒子，以及 `calibration.py` 从历史风险残差估计的场景 GP 方差、工作误差方差和相关长度。其初始化先验仍是一项声明的建模选择；后验质量随目标风险反馈更新。碰撞得分用稳定的对数非碰撞概率排序。`design.md` 给出公式、可辨识性边界和创新范围。

完整 24 个配置、每配置两个池、五个网络种子的比较如下。数值均为相对六源冻结最佳的配对均值差，单位为百分点，属于开发结果。

| 方法 | 归一化发现面积差 | 最终召回差 | F200 差 |
|---|---:|---:|---:|
| 固定行为先验排序 | −0.59861 | −1.23937 | −1.675 |
| 十六历史状态后验 | +0.42833 | +0.31866 | +1.021 |
| 连续行为后验，原误差设置 | +0.45463 | +0.28396 | +0.908 |
| 同信息 GP，原风险/碰撞预算切换 | +0.31200 | +0.13115 | +0.208 |
| 同信息 GP，始终选择碰撞得分 | +0.34665 | +0.22085 | +0.667 |
| 连续后验，期望召回增量选例 | +0.45789 | +0.27789 | +0.871 |
| 十六历史后验，估计风险误差参数 | +0.43229 | +0.31950 | +1.025 |
| 当前连续后验候选，估计误差参数、稳定概率排序 | **+0.45216** | **+0.28882** | **+0.925** |

当前候选相对最强同信息碰撞得分 GP 的面积差为 +0.10552 个百分点，召回差为 +0.06796。八个预测器留出开发配置的对应冻结最佳差为 +0.50942、+0.21853；仍不能称为独立优势。网络已在这批历史验证记录上选过模型并估计风险误差，因此这些记录不承担新方法的独立验收。

将粒子数提高到 2048 的两种子、八配置检查未改变最终召回，面积差低于 0.01 个百分点。期望召回增量选例没有共同主指标收益，未进入第二轮候选。这两个分支及原开发比较入口已收敛到 `archives/coverage_and_grid_checks.zip`：313 个条目逐字节核验后，移除四个旧脚本及相应分支记录；决策在 `archives/coverage_and_grid_decision.json`。主对照记录、开发汇总和已封存开发协议保留。稳定概率实现的三个配置完成 720 次完整开发复核；结果在 `results/log_probability/`。

## 入口与第二轮确认

- `train.py`：历史配置条件化预测器训练。
- `calibration.py`：历史风险误差似然估计。
- `verify_selector.py`：在已披露开发池中核对独立选择器。两个难例、七方法，共 2800 次查询逐项一致；输出 `results/selector_verification.json`。
- `confirmation.py`：冻结输入，测量新系统和新坐标，再运行选择、统计与物理审计；直接在 `metadrive` 环境运行，不需要 CLI 参数。
- `confirm.py`：父进程保留完整真值；选择器独立进程只收到坐标、历史预测和逐条允许的反馈。
- `evaluate_confirmation.py`、`audit_confirmation.py`：共同主指标统计、完整场景池核对和物理回放。

第二轮预设 48 个新参数配置、96 个新场景池，完整池共 196608 次物理测量；每方法每池每网络种子查询 200 次。四个主对照、两个主指标共八项精确检验，Holm 校正后均需小于 0.0125，并满足对冻结最佳及同信息强 GP 的双指标正向 bootstrap 区间。固定行为排序与十六历史状态后验另作机制对照。完整冻结协议和逐池记录位于 `results/confirmation/`；未完成前没有独立显著性结论。

本目录活动代码的六项数学/数值检查通过，另三项召回增量积分检查随该分支归档。原始九个外部 baseline、冻结方法及此前最佳的完整结果表，仍见 `../response_adaptive_testing/results/confirmation_report.md`；该报告同时保留第一轮未通过的确认结论。当前候选没有把风险 QDScore 纳入选例或主验收。

## 后验解释性诊断

`diagnose_behavior.py` 在已经披露的 24 个开发配置中复算 240 次候选轨迹，与缓存的每次 200 查询序列一致；真实配置只用于事后诊断和带额外参数信息的网络排序参考。它不读取第二轮新目标的响应。

200 查询后的控制器类型判断正确率为 96.67%，八个预测器留出配置上为 100%。均匀先验用固定平局规则判断，初始正确率为 50%；前 50 次查询的真实类型后验质量仍接近 0.5，不能据此宣称很早恢复目标类型。

三项物理参数的名义 90% 工作后验区间，在完整开发队列覆盖真实值的比例只有 41.25%、30.42%、33.75%；留出配置上为 53.75%、38.75%、45%。当前方法用于适配失效响应，参数区间尚未经过覆盖校准。真实参数下的网络排序在留出配置上也没有高于候选，说明真实参数恢复和近似预测器的失效排序价值需要分别判断。详见 `design.md` 及 `results/behavior_diagnostics/comparison.json`。

`report_confirmation.py` 已准备好审计后的完整报告：七方法的 F10/F30/F50/F100/F150/F200、两项主指标、预算上界、预算内可找全的池、类型分组、逐配置结果，以及原始池完整 baseline 表。它只在独立统计和物理审计通过后生成报告与 PNG/PDF 图。

`audit_measured_pools.py` 在收集期间核验已完成池的日志、响应数组、成本记录，并回放两个场景族的边界索引。回放结果写入最终审计使用的同一缓存，后续直接复核，不重复增加物理调用。局部进度在 `results/confirmation_audit/measurement_progress.json`；该文件不承担完整队列或显著性验收。
