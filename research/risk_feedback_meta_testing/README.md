## 方法与对照

固定既有风险骨干与 GP，学习同结构的碰撞分支和风险残差读出。普通监督使用已知历史行为与单点配对风险；元适配使用风险支持集更新后验，再用未查询碰撞监督预测。目标在线参数冻结，后验持续更新。

风险的工作观测模型为 `clip(F + noise, 0, 1)`，`F` 是高斯潜在分数。训练数据有 8,485/98,304 条风险恰好为 1，因此边界观测使用高斯尾概率，而非将 1 当作普通点密度。潜在分数的条件均值可能超过 1，实际风险及假设风险均保持在 [0,1]。核与噪声参数仍固定；截断反馈后的高斯矩近似和 logistic-normal 读出属于近似推断，不是精确贝叶斯保证。[矩匹配推断的原始方法依据](https://tminka.github.io/papers/ep/)。这些观测与数值实现由所有新对照共用，不单独作为元适配收益。

主开发对照为普通监督/元适配 × 贪心/终点约束前瞻，另加去掉终点约束的面积前瞻消融。约束保护近似模型中的预计终点发现数，实际优势由共同主指标验收，不将其称为真实召回保证。

前瞻先保留当前排序下的剩余批次，再计算假设反馈后重新选例/排序相对该固定延续的增量。没有改变未来选择或顺序时，信息收益为零；概率整体变化不额外计作发现收益。一致后验下，这与原预计延续效用相等。查询记录同时保存固定延续的概率漂移，便于检查近似读出的影响。当前使用 8 个高概率候选、8 个概率不确定候选及 16 个内部积分点，边界概率质量单独积分。

### 选择价值的数学依据

记 `q_D` 为当前碰撞概率，`S0(x)` 为排除根查询 x 后、按当前概率选出的剩余预算批次，`T(q)` 为重新选出同样数量候选的最大概率总和。更新仅使用假设风险 r，得到 `D'`。终点信息增量为

\[
I_T(x)=\mathbb E_r\left[T(q_{D'})-\sum_{y\in S_0(x)}q_{D'}(y)\right].
\]

终点评分为当前查询的概率、原批次的当前概率总和及该信息增量之和。面积评分使用同样的差分，但将剩余查询依次按 b−1、b−2、…、1 加权；这些权重来自累计发现面积的定义。

因为反馈后的最优批次不差于原批次，每个假设反馈对应的终点增量非负。若未来最优批次始终不变，该增量为零；面积增量还要求选例顺序不变才为零。

若预测是同一联合模型下的一致后验，全期望公式给出 `E_r[q_D'(y)]=q_D(y)`。因此减去固定批次未来概率、再加回其当前概率，不改变标准非短视预计效用。若神经读出或矩近似不满足这一性质，此形式避免将固定选择的概率漂移视作信息收益。以上是最优选择与全期望的标准性质，不单独声明新定理。

终点约束比较同一近似评分下的候选与贪心根动作；它不能推出实际终点召回不下降。方法最终是否有效，仍需真实物理碰撞标签、配置级配对比较和独立确认支持。

## 入口和当前状态

- `config.py`：统一数据路径、系统划分、查询与训练预算。
- `prepare.py`：逐项核对既有 SUT 与场景生成器，检查物理响应坐标、场景族和风险范围；注册开发数据划分与两个场景族各自的物理设置。
- `posterior.py`：只使用风险支持集的批量 GP 条件化，用于训练时模拟部署。
- `risk_state.py`：有界风险观测的尾概率与矩更新，按行为假设保存低秩协方差；假设观测不进入真实记录。
- `model.py`：冻结响应表示与相同参数规模的碰撞读出。
- `session.py`：只接收已查询风险的在线适配，采用 log odds 保留接近 0 或 1 时的排序精度；两个训练对照共用此数值实现。
- `planner.py`：按改变未来选择的收益评价候选，在同模型的贪心终点评分约束下优化时间加权发现量。
- `train.py`：相同训练查询标签与优化预算的普通监督/元适配训练，依据验证配置上实际部署条件下的碰撞 log loss 选取检查点。
- `test_method.py`：批量条件化与逐步在线更新、训练与部署读出、极端概率排序和冻结风险预测的数值验证。
- `finish_confirmation.py`：第三轮原选择器运行结束后，补计其输出遗漏的 F10/F30/F150，再调用冻结评价、独立审计和报告。只补派生计数，不改变选择序列、原观测、源码或物理数据。
- `evaluate.py`：模型训练完成后锁定输入，在独立子进程中运行五个开发策略；父进程保留目标参数和完整响应库，逐次披露风险。
- `summarize.py`：以物理碰撞标签独立重建发现曲线，核对风险披露、查询数量和模型终点约束；按系统配置汇总配对区间及完整结果表。

第三轮 3,360 次回放及独立审计已完成，96 个完整物理池、384 次重跑和统计重建通过。共同验收未通过：相对 matched GP 的召回 Holm p=.0185345，高于本轮 alpha=.00625；相对冻结最佳的两项主指标通过本轮检验。完整表与解释见 `results/confirmation_stage.md`。

开发数据的 96 池、196,608 条响应及 24/12/12 配置划分已检查；11 项数值验证与真实历史边界反馈的梯度检查通过，包括有界预测、条件矩、训练/部署一致性、假设观测隔离、终点约束和选择收益。真实数据检查中发现并修正了方差矩阵从单向量变为行为×场景矩阵后的查询切片接口。这些是实现正确性证据，不是性能优势。

五个种子的普通监督与元适配训练全部完成，每种方式具有相同的 260 个可训练参数与 4,000 次优化步骤。五方法、12 配置、2 池、5 种子的固定开发比较已锁定并启动，共 600 次回放。验证计时的单次前瞻约 0.2–0.6 秒，峰值显存约 2.63 GB；初始完整前瞻回放约 60 秒。未完成全部比较前不声明性能优势。

执行入口：`python -B -m research.risk_feedback_meta_testing.finish_confirmation`，只在全部 3,360 次第三轮选择完成后运行。新方法参数与结果存入本目录 `results/`，不覆盖冻结模型。

开发训练入口：`python -B -m research.risk_feedback_meta_testing.train`。训练前须执行 `prepare`；训练在冻结确认的 GPU 回放结束后开始，避免竞争其计时资源。检查记录见 `results/implementation_check.json` 与 `results/protocol.json`。

训练完成后依次执行 `python -B -m research.risk_feedback_meta_testing.evaluate` 和 `python -B -m research.risk_feedback_meta_testing.summarize`。`results/boundary_integration_check.json` 另记录真实历史风险边界反馈的梯度检查；这些实现检查均不作为性能验收结果。
