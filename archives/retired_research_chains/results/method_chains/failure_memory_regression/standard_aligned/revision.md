# 一次有记录的场景范围修订

quick 使用任务书首轮范围：单车道前车紧急制动初始净距 5–60 m。在种子 4179801 的 24 个参考执行中，24 个均发生 ego 碰撞，所以该模板没有参考通过候选，也无法建立通过／失败配对。

在同一参考控制器、5 m/s² 前车减速度下做范围诊断：60 m 与 80 m 仍碰撞；100 m、120 m、150 m 均完整通过。由此 core 将该模板的初始净距上限一次性扩为 120 m。控制器、前车刹车脚本和其他三个模板的范围没有改动。扩展范围的参考和目标版本均重新配对执行；旧 quick 试跑已被 core 取代并清理。停—保持—起步模板即使缩小初始净距，参考版也保持通过，因此保留该模板的 `boundary_missing` 回退，不再额外修改。

这些数值是研究场景参数，不是标准阈值。范围诊断的 10 次参考执行额外计入工程探索成本，不计入 quick/core 主表物理 episode。core 结果与 quick 因候选范围不同，不能直接视作同一池上的独立重复。

收敛清理后仅保留 core 正式结果。quick 和 smoke 的中间产物已删除；共享 episode 缓存也已删除，参考及目标的正式逐场景记录分别保存在 core 的 `reference_archive.csv` 和 `target_response_bank.csv`。再次执行完整实验会重新运行物理仿真。

## 50 次预算与方法收敛

参考论文的核心启发是：一个历史失效点只是入口，真正可迁移的信息是失效区与通过区的交界及其不同方向。本实验没有声称复现论文的 FSB/DSB 搜索；它将历史实测失败/通过配对作为局部边界证据，限制新版本候选为参考版通过的场景，再逐次查询新版本。

新增 `FBRT-RegionBandit` 将两层信息结合：在每个功能场景内，按历史安全裕度与失效边界邻近程度的排名之和选点；在功能场景之间，根据已经查询到的新版本回归碰撞使用 UCB 分配后续预算。没有历史失效边界的功能场景仍能按历史裕度参与，因此不会被边界分数永久排除。该方法只使用历史记录和此前已查询的目标结果；完整目标结果库仅用于离线评估。

正式预算改为每个版本×种子 50 次，检查点为 5、10、20、50。使用已保存的 480 个参考、960 个目标实测 episode 离线重放，新增物理仿真 0 次。9 项任务中，`FBRT-RegionBandit` 在 @5 和 @50 均检出 9 项；@50 平均找到 20.22 个回归碰撞，`HistoryRank-UCB` 为 19.67，`HistoryMargin` 为 18.56，原 `FBRT-Adaptive` 为 16.11。完整逐次查询和功能数见 `core/queries.csv`、`core/summary_by_revision.csv` 与 `core/report.md`。

这仅是同一实测结果库上的方法开发对比：改动源于观察该库的早期结果，不能作为独立验证集上的优势证明。场景种子也不是独立缺陷；下一步如需支持更强的泛化结论，应固定方法后更换控制器修订或场景样本再测试。

无需重跑仿真即可复现 50 次选择实验：`conda run -n metadrive python -m method_chains.failure_memory_regression.experiment --replay-measured-bank`，随后运行 `conda run -n metadrive python -m method_chains.failure_memory_regression.report --reuse-replay`。
