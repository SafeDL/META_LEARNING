# 收益校正风险测试

收益校正风险测试（GCRT，Gain-Calibrated Risk Testing）利用已有测试记录，优先选择可能危险的自动驾驶场景，并根据当前测试反馈判断何时停止。

车辆切入、跟驰过程中的前车紧急制动分别训练模型、选择场景和决定测试次数。方法流程为：

**历史风险预测 → 逐次选择场景 → 真实测试与风险更新 → 校正剩余发现预测 → 继续或停止。**

历史响应关联编码器学习场景之间的风险联系；剩余发现数量预测网络估计继续测试还能找到多少危险场景。每完成五次测试，用实际发现比例校正预测；任务之间可用新增记录更新预测网络。

## 运行

在项目根目录、现有 `metadrive` 环境中执行：

```powershell
conda activate metadrive
python -B -m methods.gcrt.build
python -B -m methods.gcrt.evaluation
```

`build` 从历史记录构建模型，已有组件直接复用；`evaluation` 复用或补齐完整测试轨迹，完成停止评价、一次网络更新和成本报告。当前实验使用已有实测响应回放。

只重新汇总结果时运行：

```powershell
python -B -m methods.gcrt.report
```

## 实验设置与进展

- 功能场景：车辆切入、前车紧急制动。
- 三个场景测试集：参数范围相同、Sobol 采样点不同；每个测试集每类 1024 个场景。
- 被测驾驶控制器：IDM、FVDM、IDM＋MOBIL、碰撞时间值迭代、恒速预测蒙特卡洛树搜索、PPO。
- 历史来源：六种 IDM／FVDM 配置。固定随机种子 11，每类最多测试 200 次，包含前 10 次共同初始化。
- 危险判定：实测风险 `R > 0.5`。评价发现数量、危险场景覆盖率和完整成本。

已完成 36 条完整测试轨迹、提前停止评价和一次周期更新，共 7200 次完整轨迹计费查询，无新增物理仿真。工程回归检查已通过 164 项测试。

下表为预先留出的 **IDM、IDM＋MOBIL** 控制器在三个测试集上的平均结果，固定预算与提前停止使用相同任务：

| 功能场景 | 平均测试次数 | 发现数：固定 → 停止 | 发现数保留比例 | 覆盖率：固定 → 停止 |
|---|---:|---:|---:|---:|
| 车辆切入 | 152.50 | 116.00 → 113.83 | 98.13% | 98.67% → 96.95% |
| 前车紧急制动 | 125.83 | 100.67 → 98.17 | 97.52% | 62.88% → 62.55% |

按已测执行与计算耗时估算，同类模型复用 100 次、计入构建和维护后，相对固定 200 次测试的平均总成本分别下降 **7.68%、3.55%**。完整预算的发现能力、逐控制器覆盖率与全量测试成本见[结果报告](results/gcrt/comparison.md)。

## 论文与交流规范

- 使用简明中文和业内常用术语，直接说明问题、技术和结果；避免口头禅、临时造词、反复自我否定及过度严苛、防御性的表述。
- 方法标题使用中文，英文全称与缩写集中定义。对比方法使用真实名称，不用“上一版”“冻结方案”等开发代称。
- 明确写出功能场景、驾驶控制器、历史来源和场景测试集，避免“评价池”“六个系统”“三个模型”等无定义指代。
- “场景选择规则”决定下一步测试哪个场景；“收益”指新增危险场景数量；“剩余发现数量预测”用于停止判断；“停止校准”用于确定阈值。五次连续测试称为“测试片段”。
- 区分风险后验更新、任务内收益校正和神经网络参数训练。每轮执行一个场景；持续学习使用已完成的真实测试记录，更新后的网络在后续任务评价。
- 危险场景按 `R > 0.5` 定义，不能直接称为碰撞。覆盖率是已发现数量占该任务全部危险场景的比例；控制器等权的宏平均与合并计数覆盖率分别报告。
- 区分当前实现、已完成实验和拟议改进；完整保留预设结果。创新可采用其他领域的成熟技术，重点解释其在自动驾驶测试中的作用和收益，补充实验围绕尚未回答的问题安排。
