# FBRT 场景、被测算法与主车初始状态审计

本审计使用 `conda activate metadrive` 对已冻结的 v2 场景银行作静态检查，并以新的 v4 执行契约进行物理重放。下方 GIF 均由 **实际 20 Hz 轨迹**绘制，每 0.2 秒显示一帧；蓝色为主车，橙色为前车，紫色为后车，红色为静止车。左右画面各自跟随主车，顶部显示当前时刻、速度、动作、碰撞状态和初始状态。图形是轨迹俯视图，不是 simulator 原生像素渲染。

## 1. 被测算法确实运行了吗？

**四类策略代码均已在统一执行器中实际运行。**原 v2 方法排名只用了 MOBIL 与 PPO；VI-TTC、MCTS-CV 是本轮新增的运行冒烟，每种仅在 S02、S05 各执行一次，没有对应修改版或足够场景，不能与原排名作性能比较。

- v4 MOBIL 主车的实际类为 `RearGuardIDMVehicle`，每个完整的 12 秒场景有 240 次原生 `act()` 调用和 12 次 `mobil()` 判定。S05 正常版无碰撞；关闭后车保护版记录 1 次实际保护条件绕过，并在 2.70 秒与后车碰撞。[MOBIL 正常版与修改版 GIF](gifs/policy_mobil_guard_pair.gif)
- v4 PPO 主车的实际类为 `MDPVehicle`，控制策略类为 `PPOPolicy`，加载权重的 SHA-256 为 `386ef97bead6fab69f863fca9f1106a2c8ca2400a0bc896cae3e195b5e094b28`。S02 正常版给出 42 次离散决策，观测延迟版给出 43 次；共同决策步中有 7 次动作不同，碰撞时刻分别为 8.40 秒和 8.60 秒。[PPO 正常版与延迟版 GIF](gifs/policy_ppo_delay_pair.gif)
- 原 v2 物理银行的 160 条 PPO 执行记录均有决策动作，MOBIL 修改版共记录 54 次后车保护绕过。原有 `ego_action_count=0` 对原生 MOBIL 是预期值：它通过车辆类的 `act()` 与 `mobil()` 控制，而非 PPO 的离散动作接口。v4 加入了原生调用计数，以免把这个 0 误判为“没有运行”。
- VI-TTC 实际实例化 `ValueIterationPolicy`：S02 有 16 次动作，S05 有 60 次；MCTS-CV 实际实例化 `MCTSCVPolicy`：S02 和 S05 各有 24 次、16 次动作。[两者在 S02 的 GIF](gifs/policy_vi_mcts_S02.gif)、[在 S05 的 GIF](gifs/policy_vi_mcts_S05.gif)。它们通过与 PPO 相同的离散动作接口控制主车，但 v4 使用本执行器声明的奖励配置，不能把两次冒烟当作旧复现实验的等价性能估计。
- VI-TTC 在 S02 的原始结果记录了主车碰撞，却没有填碰撞对象。末帧主车和移动前车同帧标记碰撞，因此审计另记 `inferred_collision_partner_role=lead`，保留原始空字段。这暴露了当前碰撞对象提取器在碰撞后车辆分离时可能漏标；此标签不参与原 v2 排名。

运行时类、调用计数、动作数、测量警告和逐个结果在 [audit_manifest.json](audit_manifest.json) 与 [episodes.jsonl](episodes.jsonl)。PPO 权重的 Stable-Baselines3 保存版与运行版仍有兼容警告；确定性推理已运行，但若要完全排除版本影响，应在匹配版本环境再复核。

## 2. 场景参数与实际事件

原 v2 选中 S01、S02、S05、S06、S08，每类 16 个，总计 80 个场景、四个构建共 320 次执行。80 个场景均落在声明的研究范围内；静态检查未发现初始车辆重叠、车道数错误、后车速度超过本实验设定的 35 m/s，或重复的“构建×场景”执行。新审计的 54 个 v4 场景执行均没有初始碰撞，主车初始状态与配置一致，场景动态事件检查通过。

| 场景 | 参数及核查重点 | 人工检查 GIF |
|---|---|---|
| S01 切入 | 初始纵向间距 8–60 m，换道时间尺度 1.5–3.0 s；示例第一次侵入在 1.70 s，晚于 1.00 s 的事件开始。 | [S01 两种策略](gifs/scene_S01.gif) |
| S02 切出、静止目标 | 初始间距 8–40 m；在事件开始时，前车至静止车的构造间距为 40–90 m。**旧检测器把 64/64 次切出记为 0 s；v4 示例改为 1.35 s，换道完成在 1.95 s。**PPO 示例在 8.40 s 撞的是移动前车，不是静止车。 | [S02 两种策略](gifs/scene_S02.gif) |
| S05 后车换道 | 后车初始间距 8–60 m、相对接近速度 0–10 m/s；构造出的后车速度为 25–35 m/s。正常版保护条件阻止危险换道，关闭后车保护会发生后车碰撞。 | [S05 两种策略](gifs/scene_S05.gif)、[正常版与修改版](gifs/policy_mobil_guard_pair.gif) |
| S06 移动前车 | 初始间距 15–90 m、前车速度 20–27 m/s，主车基准速度 25 m/s；示例是同车道跟驰，没有脚本换道事件。 | [S06 两种策略](gifs/scene_S06.gif) |
| S08 切入后制动 | 初始间距 10–60 m，前车制动 1–6 m/s²；示例 1.55 s 首次侵入、3.00 s 完成并线、3.35 s 开始制动，事件顺序正确。 | [S08 两种策略](gifs/scene_S08.gif) |

**场景合理性结论有边界。**这些数值是研究压力测试范围，检查通过表示几何、速度和脚本时序自洽，不等于所有情形都符合某项认证标准。S02 的车辆布置是几何上有效的，但用整段 episode 的“任何主车碰撞”作为静止目标失效标签会混入切出后的前车追尾。原 v2 两个 PPO 构建在 S02 的 31 次碰撞全部指向移动前车。因此 **原 v2 的 S02 结果不能证明静止目标处理能力**；需要把碰撞对象纳入功能标签，并重新抽样主车初始状态。其他 9 张目录卡没有进入当前五场景执行银行，不能据此宣布已通过物理验证。

新的初始状态角点审计确实找到了 S02 的目标失效：主车初始为车道 1、25 m/s 时，PPO 正常版在前车切出后的 **4.25 s 撞静止车**；车道 0、25 m/s 时则在 7.85 s 撞移动前车。车道 1、20 m/s 时，PPO 正常版仍撞前车，而观测延迟版在 4.70 s 撞静止车。因此失效对象受到初始车道、速度和观测延迟共同影响，不能从五项同时变化的角点结果单独归因。[S02 初始状态角点 GIF](gifs/ego_corner_S02.gif)、[固定 20 m/s 仅换车道](gifs/ego_s02_lane_0_vs_1.gif)、[固定 25 m/s 仅换车道](gifs/ego_s02_speed25_lane_0_vs_1.gif)、[车道 1 下的 PPO 版本对照](gifs/policy_ppo_delay_lane1.gif)。

## 3. 主车初始状态进入参数空间

新 [参数定义](../../../../../configs/fbrt/ego_initial_state_audit_v3.yaml)和[已执行参数表](ego_initial_state_manifest.csv)包含：

| 主车参数 | 审计范围 | 说明 |
|---|---:|---|
| 初始速度 | S02: 15–25 m/s；其余已选模板: 20–30 m/s | S05 单变量示例 20/25/30 m/s；S02 PPO 加测 25 m/s |
| 初始车道 | 0 或 1 | 背景车按主车车道镜像布置 |
| 初始纵向位置 | 100–140 m | 用于检查绝对坐标对策略的意外影响 |
| 车道中心横向偏移 | −0.25 至 +0.25 m | 保证主车仍在车道内 |
| 初始朝向偏移 | −0.035 至 +0.035 rad | 约 ±2.0° |

相应的人工对照：[速度 20 与 30 m/s](gifs/ego_speed_low_vs_high.gif)、[车道 0 与 1](gifs/ego_lane_0_vs_1.gif)、[纵向位置 120 与 140 m](gifs/ego_x_120_vs_140.gif)、[横向偏移 0 与 0.20 m](gifs/ego_lateral_0_vs_020.gif)、[朝向 0 与 0.03 rad](gifs/ego_heading_0_vs_003.gif)。五个模板另各有一组低端与高端初始状态对照：[S01](gifs/ego_corner_S01.gif)、[S02](gifs/ego_corner_S02.gif)、[S05](gifs/ego_corner_S05.gif)、[S06](gifs/ego_corner_S06.gif)、[S08](gifs/ego_corner_S08.gif)。主车当前的运动状态被实际初始化；新场景的选择器特征从原来的 2 维扩为 **2 个交通参数 + 5 个主车初始状态参数**，并以独立上下文隔离旧实验。角点对照同时改变五个状态参数，适于发现交互和进行人工检查；单变量对照用于区分具体因素。

审计还查出 highway-env 的原生 MOBIL 默认由绝对 `x+y` 初始化换道计时器。早期 v3 诊断仅将车辆整体平移 20 m，就让 S05 碰撞时刻从 5.30 s 变成 4.50 s；差异来自策略内部计时相位，而非交通几何。v4 对 MOBIL 固定计时器起点后，同一平移的相对轨迹最大残差为 `6.3e-13`（正常版）和 `4.3e-14`（修改版）；完整旧 v3 诊断留在相邻的 `validation_audit_v3/`。固定计时器会改变与旧 v2 的执行动力学，因此 v4 是**独立审计契约**，不能直接用新轨迹替换 v2 方法排名。

## 复现与范围

```powershell
conda run -n metadrive python -m method_chains.failure_memory_regression.audit_v4
conda run -n metadrive python -m pytest method_chains/failure_memory_regression/tests/test_ego_initial_v4.py -q -p no:cacheprovider
```

原银行 320 次、v3 诊断 26 次、v4 修正审计 54 次，共 **400/400** 次新增物理执行。重复运行审计会读取缓存并重绘 GIF，不再增加物理执行。主方法实验的 80 个原场景仍只固定主车初始状态，因此其 Memory/NoMemory 排名尚未检验扩展后的七维场景空间。
