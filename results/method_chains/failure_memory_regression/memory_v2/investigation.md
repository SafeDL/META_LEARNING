# FBRT-Memory v2 工程与实验诊断

本记录针对“FBRT-NoMemory 为何高于 FBRT-Memory，以及为什么只运行 MOBIL”进行工程核查。以下计数来自固定的 80 个场景、四个被测构建和逐次查询日志；这是一次开发实验，不是独立确认实验。

## 被测系统范围

旧的 `sut_algorithms/highway_env/registry.py` 注册了 `idm_mobil`、`vi_ttc`、`mcts_cv`、`ppo_ece` 四种策略。本次计划的 FBRT v2 新银行明确只指定两种机制、各两个构建：`mobil_ref_v2`、`mobil_rear_guard_off_v2`、`ppo_ref_v2`、`ppo_obs_age020_v2`。`vi_ttc` 和 `mcts_cv` 有原有策略工厂，但没有进入 FBRT v2 的 `build_spec_factory`，统一执行器的外部策略适配器也只实例化 PPO。因此，四个构建不等于四种独立算法。

此前只看到 MOBIL，是因为 `assets/ppo_ece/vd_1_5_trial_1.zip` 缺失。先前报告称“仓库没有获取流程”是错误的：`replications/highway_sut_selection/assets.py:fetch` 已有固定提交、文件大小与 Git blob SHA-1 校验。现已调用该流程一次，下载并校验 PPO ZIP（SHA-256 `386ef97bead6fab69f863fca9f1106a2c8ca2400a0bc896cae3e195b5e094b28`）；来源与版本见 `ppo_asset_provenance.json`。四个构建的 320 条物理 episode 已完成，共用总上限 400。模型存档使用 Stable-Baselines3 2.7.0，当前推理环境为 2.3.0；加载时训练日程字段有兼容警告，但确定性预测和两个 PPO 构建的冒烟场景均完成。

## NoMemory 高分的直接原因

| 新银行任务 | 真实失效分布 | 20 次查询时 FBRT-Memory | 20 次查询时 FBRT-NoMemory |
|---|---|---:|---:|
| MOBIL 正常版 → 后车保护关闭版 | 80 个候选中 12 个新增碰撞，全部在 S05 的 16 个样本内 | 1/12 | 12/12 |
| PPO 正常版 → 观测延迟 0.20 s 版 | 61 个父版通过候选中 0 个新增碰撞 | 0，召回率无定义 | 0，召回率无定义 |
| 独立 agent 顺序：MOBIL 正常版 → PPO 正常版 | PPO 正常版 80 个候选中 19 个碰撞 | 14/19 | 17/19 |

MOBIL 回归的 NoMemory 在第 6 次查询发现第一起 S05 碰撞，此后集中查 S05；它的 20 次查询中有 14 次落在 S05，命中 12 次。Memory 只查了 2 次 S05，首次碰撞在第 19 次。NoMemory 不是随机方法：它仍用几何覆盖特征、贝叶斯目标更新和“父版通过”的候选过滤，只移除了历史标签先验与历史失败中心。

这项回归开始时，父版 MOBIL 的 80 条记录全部通过，因此 `build_pattern_cards(history)` 返回 **0 张初始失败卡**。全部 20 条 FBRT-Memory 查询的 `contributing_pattern_ids` 均为空；第 19 次才新增一张目标失败卡，第 20 次又按预设规则执行覆盖采样。旧银行的失败卡只属于其他模板或物理上下文，不能直接当作 S05 的同上下文证据。因此这里主要比较的是“由父版全通过记录得到的风险先验”和“NoMemory 的宽松先验”，没有实际检验历史 S05 失败模式的迁移。

离线重算首轮预测显示，Memory 的 S05 父版先验截距约为 `-2.00`，S05 候选首轮最高失败评分约 `0.224`；其 S01 最高约 `0.318`。NoMemory 各模板先验截距均为 `0`。这些分数是 32 次后验采样的排序分数，不应解释为已校准碰撞概率。父版全部通过对一个有意引入回归的目标版本形成负迁移，是当前结果的合理机制解释；单次排序轨迹本身不能证明所有先验都无效。

## 场景和指标的限制

新银行在五类场景中仅有 S05 对 MOBIL 修改产生新增碰撞，且 S05 16 个样本中有 12 个失败。方法只要早早识别该模板，就容易取得接近满分；这不能代表多种失效模式上的搜索能力。

PPO 正常版有 19 个碰撞：S02 16 个，S05 3 个。延迟观测版有 18 个碰撞，且在 61 个父版通过候选中没有新增碰撞；这项 PPO 版本回归没有可发现的正例。顺序测试的首个 agent 是零碰撞的 MOBIL 正常版，故无法向后续 PPO 传递失败卡。PPO 会话里 Memory 的模式贡献来自本会话已查询到的 PPO 碰撞，并非上一个 agent 的失败经验。

S02 的功能解释需要更谨慎：两个 PPO 构建在 S02 共出现 31 次自车碰撞，碰撞对象均是移动前车，而非被揭示的静止目标。当前 `first_exit_s` 检测器还把 S02 的 64/64 条 episode 记为 `0.0 s`，因为它在 reset 时用目标车道判断尚未开始的离开动作。该时间戳无效；碰撞标签和碰撞对象记录仍保留原始测量，选择器的输入和计数均不依赖该时间戳。

## 已修正的工程问题

- 旧 `target_response_bank.csv` 的 960 条结果原先被导入为 `historical`，使总模式库与源模型包含本应隐藏的评估标签。现在将其标为 `evaluator_only`，上下文历史视图显式排除该类记录；真实运行的候选查询仍通过隔离的 oracle 揭示。
- 原评估器在 PPO 权重可用时没有执行 PPO 版本回归；现已补上 61 个父版通过候选的离线评估，并如实标记“未观察到新增回归”。
- 原跨 agent 汇总错误地把所有任务都按“父版通过、新版失败”计数，导致 PPO 独立测试虽查到碰撞却报告为 0；现按任务类型计数，并保留两阶段各自的会话文件。
- 原两阶段会话共用 `method/repeat_0` 路径，第二阶段覆盖第一阶段；现采用含任务 ID 的独立目录。被覆盖的旧文件移至 `superseded_runs/`，不计入当前查询账本。
- 重复离线评估曾把先前会话已查询的 MOBIL 样本误作新首会话的初始历史；现冻结首会话视图，并将总归档重建为 1,440 条 legacy 记录加最终 Memory 分支的 40 条真实查询观察。当前有 1,480 条记录、3,640 次逻辑查询、320 次新增物理执行。
- 跨策略任务原先只执行一次 Random，未满足计划中的 10 次离线重复；现为每次重复建立隔离分支并使用独立随机种子。PPO 正常版 20 次查询下，Random 平均发现 4.3/19 次碰撞，FBRT-Memory 发现 14/19，FBRT-NoMemory 发现 17/19。

## 结论边界

当前结果支持的说法是：在这批场景和预算中，NoMemory 在两个有正例的目标任务上优于 Memory；MOBIL 结果主要受单一失败模板与全通过父版先验影响。它不支持“失效模式记忆普遍无效”，也尚未提供一次真正有先前失败卡可迁移、且目标具有多类非饱和新增失效的确认实验。若要扩展被测算法，需为 `vi_ttc`、`mcts_cv` 增加 FBRT BuildSpec 与动作适配，并在看结果前冻结适用场景和版本关系；不能把它们直接替换成既有 PPO 结果。
