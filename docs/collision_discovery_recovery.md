# 128次查询下的后续开发协议

## 授权、目标与冻结边界

用户已选择：保留128次查询预算，下一轮改用可达的漏检减少比例作为门槛，并保留首轮失败结论。本协议是原[执行方案](collision_discovery_plan.md)的后续开发补充，不修改原440项主实验、80项带宽实验及其5个百分点门槛。

后续门槛固定为：相对开发集最强基线，谱系等权平均漏检率至少减少50%；平均去重碰撞数不降低；至少两个存在碰撞的谱系获得正召回收益。定义为

\[
\eta=\frac{R_{\mathrm{new}}-R_{\mathrm{ref}}}{1-R_{\mathrm{ref}}}\geq0.50.
\]

先在各谱系内汇总，再对谱系等权汇总后计算该比例，不对每项任务的漏检减少比例求平均。全库无碰撞任务保留数量与成本，召回率为不适用。若基线已经全部召回，比例不适用，不以零除或任意平滑宣称通过。

首个后续协议冻结时的最强基线为FSBO，平均召回率95.4709321476%，因此当时新门槛要求召回率至少97.7354660738%。它仍然是研发投入门槛，不代表统计显著性。报告配对分层自助法区间、原始数量、召回和完整曲线。不得以改善预测损失替代发现收益。后续引入更强对照时，依据该轮预先登记的最强基线重新计算所需召回率。

后续始终使用8个历史系统、4个开发系统，切入/切出每任务512个候选，8次共同随机初始化计入128次预算，选例种子11、23、37、53、71，环境种子81001。正式目标、旧最终目标不进入后续设计或选参。已有执行库只读，第一轮补采上限2048次物理调用保持不变。

## 当前待检验机制

既有冻结编码器、匹配训练和宽支持集训练均未优于FSBO。FSBO每轮使用全部已付费标签重新适配核；原型只做固定核的顺序近似更新。这提示下一轮检验“目标反馈能否修正历史响应所定义的相似性”。该解释是待检验假设。

首个新原型以同一FSBO历史初始化为物理/目标分量，额外构建来源独立的历史碰撞响应坐标。每个历史系统单独训练固定的梯度提升分类器，输出候选场景的碰撞概率；仅使用该来源的512份历史记录，不使用开发标签训练这些响应预测器。概率裁剪后转为归一化logit坐标。核定义为

\[
K(x,x')=K_{\mathrm{FSBO}}(x,x')+
\sum_s a_s^2\exp[-(r_s(x)-r_s(x'))^2/(2\ell_s^2)].
\]

来源核系数非负，初始来源方差总和为1，初始响应长度尺度为0.3。原FSBO网络、均值和训练协议不变。每次查询后从相同历史初始化出发，以全部已付费碰撞标签做10步Laplace证据优化，学习率0.003；在线不使用间距、TTC或轨迹。仅按碰撞概率贪心选例。

预先固定两个新配置：`response_adaptive`同时更新来源系数、来源长度尺度及FSBO参数；`response_fixed`固定来源核参数，只更新相同FSBO参数。无响应消融为原FSBO。响应预测器固定使用150轮、学习率0.1、最多15个叶子、最小叶样本12、L2正则1、随机种子1601，不对本轮结果搜索这些设置。

这80项运行用于机制开发。仅当主要门槛和对应机制对照均通过，才进入后续阶段；自适应版本还须比固定版本获得更高召回且数量不降低。若失败，完整保留两组结果及成本，再针对已观察的缺口提出单独冻结的改进，不将失败版本排除在研究记录之外。新的核组合和来源特征本身不预先声称为独创贡献。

## 命令、输出与验证

后续入口为 `python -B -m benchmark.discovery_recovery freeze`（冻结协议）、`run`（80项隔离回放）、`report`（验收判断）。协议位于 `results/benchmark/collision/discovery/recovery/protocol.json`；运行位于 `results/gcrt/collision/discovery/recovery/runs/`；门槛、索引、成本和统计位于 `results/benchmark/collision/discovery/recovery/`。实验前冻结门槛和配置，实验后不得覆盖为不同设置。

先验证：响应核对称且半正定、关闭响应核时与原FSBO概率一致、梯度可用且固定参数不更新、来源排列不改变预测、历史预测器拒绝非历史档案、隔离选择器不接收全库标签或轨迹、初始化计入预算。每项运行保留逐次预测、已付费标签、账本、参数与计时记录。全库分母仅由评估端读取。

原C/D/E入口仍保留首轮失败检查。后续通过时通过独立的后续准入记录进入后续工作，保留旧检查的真实结论；不得把旧门槛改成通过。场景扩展、目标资格检查、留家族实验及完整仿真成本继续遵循原方案。

## 碰撞响应适配后的已知结果与下一项验证

上述80项运行已经完成并独立复核：自适应版平均碰撞数36.675、召回率95.658267%，漏检减少4.1363%；固定版36.925、95.984848%。自适应版没有优于固定对照，后续门槛未通过。原FSBO为36.600、95.470932%。这不是机制成功。

共同漏检诊断覆盖8个开发任务的配对种子11，保留在`recovery/miss_diagnosis.json`。PPO切出的两项共同遗漏在所有来源的碰撞响应预测中均偏安全。这提示仅保留二值历史碰撞可能丢失接近失效的结构；不能由这两项观察直接声称连续安全响应有效。

下一项冻结验证利用原历史档案已有的最小间距、TTC，增加连续历史响应坐标。每来源每安全变量单独拟合同配置的150轮梯度提升回归器，监督直接取现有`archive.auxiliary`，不增加仿真或目标反馈。响应预测以该来源历史标签的均值、三倍标准差归一化，分母下限0.1，裁剪到[-1,1]。将16个安全坐标与8个碰撞坐标共同输入相同加性响应核，初始响应总方差仍为1。基线和目标适配设置均保持不变。

主方法预先指定为`safety_fixed`，检验固定连续响应几何；`safety_adaptive`仅作辅助比较，不因开发结果较好而自动改为主方法。每版本40项，共80项。准入仍要求50%漏检减少、数量不降低和至少两个谱系正收益；连续响应主方法还必须比碰撞坐标固定对照`response_fixed`有更高召回且数量不降低。这里检验历史信息表达，不再把来源参数优化列为待证明的主贡献。

入口为`python -B -m benchmark.discovery_safety freeze`、`run`、`report`。独立输出位于`results/benchmark/collision/discovery/safety_response/`和`results/gcrt/collision/discovery/safety_response/runs/`。新实验同时改变历史监督信息的使用方式，报告须明确该点，不能把收益全部归因于核参数优化。所有新旧失败、调参投入与运行成本共同保留。

## 历史预测的几何诊断与后续对照

在连续响应开发回放期间，另做了只使用历史档案的4折交叉验证，8来源×2场景，固定折种子1607。增加相对运动特征后，切入Brier从0.06519降至0.04417，切出从0.04848降至0.02877；安全响应MAE也分别从0.11430降至0.08511、0.03342降至0.02713。该诊断不读取开发或正式目标标签，完整结果保存在`geometry_diagnosis/report.json`。

新增特征由场景初始参数直接计算：事件开始、中点、结束时按匀速外推的纵向间距，相对速度平方与间距之比，预计追及时刻与事件阶段的差；切出另有预计抵达障碍时刻和所需制动强度。它们只是初始相对运动的坐标，不模拟目标控制器，也不使用真实目标轨迹。公式和固定归一化见`methods/gcrt/response_geometry.py`。

若完整连续响应实验未通过，则冻结下一项80运行比较：主方法`geometry_response`只改变历史响应预测器的输入特征；对照`kinematic_kernel`直接将这些相对运动坐标输入同一个加性核，不读取额外历史响应。其余FSBO初始化、响应总方差、长度尺度、目标10步适配、128次预算保持一致，来源核参数固定。

该物理特征对照与原四项强基线共同参与“最强基线”的选择，不能只对原FSBO计算有利收益。主方法须将最强基线的剩余漏检减少至少50%，数量不降低，且至少两个谱系有正收益；还须比原始特征的连续历史响应版本有更高召回且数量不降低。若物理特征对照解释全部收益，不认定历史响应迁移机制成立。若最强基线达到100%召回，则漏检减少比例不适用，不宣称通过。

命令为`python -B -m benchmark.discovery_geometry_diagnosis`（历史诊断），以及`python -B -m benchmark.discovery_geometry_search freeze/run/report`（逐个执行阶段参数）。协议与报告位于`results/benchmark/collision/discovery/geometry_search/`，运行位于`results/gcrt/collision/discovery/geometry/runs/`。历史预测的交叉验证改善仅是提出这一实验的依据，不能作为主要发现指标的替代证据。

## 已完成结果与下一步诊断范围

上述三轮后续开发均已完成，共240项运行、30,720次等效查询，新增物理调用为零；每轮80项均已独立复核。统一[结果、曲线和成本](../results/benchmark/collision/discovery/post_decision_summary/report.md)保留全部主方法和辅助对照。

相对运动响应主方法为36.800个碰撞、95.970273%召回；直接物理特征对照为36.750个、96.051630%，成为该轮最强基线，50%漏检减少门槛相应要求98.025815%召回。主方法没有通过该轮准入，不因相对原FSBO有小幅改善而改写结论。

上述证据不支持继续只增加历史响应特征。随后检查目标独立分量的能力：现有原型冻结历史编码器做顺序近似后验，FSBO每轮还会适配目标表示。检验强目标适配分量能否与历史来源核形成互补，同时增加“只组合两种目标模型”的对照，以隔离一般模型集成与历史来源贡献。这保持实际碰撞为唯一在线监督，不新增查询权限。该项随后按下述200项配对比较实施；预测模型并集仍不视为128次预算内可实现的收益。

## 强目标分量：200项固定开发实验

互补性诊断现已覆盖全部40项配对开发任务，比较FSBO与10个既有版本的交集及双向独有发现。结果位于`complementarity/report.json`和同名Markdown。每个并集实际合计两次128查询，不是128次预算下的结果，也不是重新在线融合的性能上界。它支持检查模型互补，但不足以证明融合可通过门槛。

下一项比较固定为五方法×40任务，共200运行：

| 方法 | 固定差异 |
|---|---|
| `hybrid_local`（主方法） | 来源独立核，全部来源与目标深核统一局部可靠性更新 |
| `hybrid_global` | 同一组预测器，可靠性更新改为全局 |
| `hybrid_shared` | 同一原历史编码器，来源改为共享核，保留局部更新 |
| `target_local` | 仅组合冻结物理核目标GP与目标深核，不提供历史来源后验 |
| `gp_target_local` | 仅组合从零适配的物理GP与目标深核，不提供历史来源后验 |

目标深核使用原FSBO历史初始化，每次获得真实标签后从该初始化重新拟合全部已付费碰撞标签，10步、学习率0.003。从零物理GP对照同样每轮重置，10步、学习率0.01，与原无历史GP一致。历史来源仍使用同一原编码器、原先验均值和逐次ADF更新，避免同时改变历史网络。

历史来源与旧物理目标分量保留原0.75/0.25比例，另加入质量为0.25的FSBO分量，统一归一化，得到0.60历史、0.20物理、0.20深核。两个仅目标对照分别采用两个分量等权初始化。全部分量的可靠性都使用查询前预测；内部来源后验的权重更新关闭，避免与外层可靠性重复计入。局部带宽固定0.30，全局对照令κ=1。仍只按混合碰撞概率贪心选例。

主方法须达到50%剩余漏检减少、数量不降低、至少两个谱系正收益；局部版本还须比全局版本召回更高且数量不降低，来源独立核还须优于共享核对照。原四项强基线、已有物理特征对照和两个新仅目标融合对照共同参与最强基线选择。一般目标模型集成足以解释收益时，不认定历史来源机制成立。

入口为`python -B -m benchmark.discovery_adaptive_target freeze/run/report`，逐个执行阶段参数。协议和结果位于`results/benchmark/collision/discovery/adaptive_target/`，运行位于`results/gcrt/collision/discovery/adaptive_target/runs/`。正式阶段仍须从历史档案重新训练与最终核一致的模型，当前冻结旧编码器只用于机制开发。

该轮已完成并独立复核，主方法36.450个碰撞、95.464674%召回；共享来源核对照36.625个、95.523057%，仍未通过门槛。原最强物理特征对照96.051630%继续作为参考。独立审计重建25,600条反馈与可靠性更新、143,360次来源分量概率，并完成600次FSBO和120次从零GP数值检查及600次完整候选选点检查；四种损坏记录均被拒绝。

随后完成[联合响应方案](collision_discovery_joint_response.md)的4个历史训练模型、16个来源后验和280项完整搜索，全部独立复核。相对同反馈目标基线，主方法仅减少10.025641%漏检，未通过门槛；局部可靠性和完整协方差未形成稳定独立收益。现根据相同付费前缀诊断，执行[独立物理分量验证](collision_discovery_physical_mixture.md)，保留128预算、50%漏检减少与原失败结论，强基线扩展为全部此前有效对照及同CUDA后端FSBO。新矩阵仍属于开发阶段。
