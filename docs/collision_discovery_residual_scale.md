# 用历史系统间差异估计迁移残差尺度

## 问题与本轮边界

阶段反馈的两组240项同前缀诊断均没有显示稳定的剩余碰撞排名收益，暂不扩大这一方向。回到只使用在线碰撞Boolean的迁移模型，检验一个更小的变化：**把绝对风险核直接作为跨系统残差核时，其幅度是否合适？历史系统之间的响应差异能否在接触开发目标之前估计这一幅度？**

当前来源分量使用历史后验均值与协方差，再加目标核。该结构已有文献基础，本轮不宣称其本身原创。目标核在已有训练中用于拟合单个系统的绝对风险，尚未通过历史系统之间的预测来估计残差幅度。本轮只估计每类场景一个非负标量β，不增大网络、不新增在线反馈、不更换驾驶系统或场景。

来源条件先验为

\[
m_s(x)=\mu_s(x)+(m_t-m_{\mathrm{init}}),\qquad
K_s(x,x')=C_s(x,x')+\beta^2 K_t(x,x').
\]

独立目标分量保持原始`m_t,K_t`，不乘β。来源总先验质量0.75，来源内家族等权，独立目标0.25。外层物理GP保持0.10质量。局部可靠性带宽固定0.30，按查询前碰撞似然更新；全局可靠性作为同核对照。均值参考使用相应目标初始化的均值，避免更换初始化时平移历史均值。

目标分类器固定使用现有FSBO初始化。已有同前缀诊断中，它对PPO剩余点90的排名优于联合初始化，但该现象不能当成新在线发现收益。历史来源后验继续复用原联合响应教师及历史碰撞/间距；只取分类通道。这样隔离残差幅度与在线目标表示，不同时重新设计来源编码器。

## 1. 历史训练前缀与缓存

只用8个历史对象，切入/切出各512个历史坐标。每次将一个历史对象视为伪目标，并从来源后验上下文中排除它，剩下7个来源。已有教师曾在全部历史对象上训练，因此这里是历史内部的参数学习，**不是严格留系统泛化验证**。开发系统不作为伪目标，不读取其碰撞或轨迹用于选β；既有基础检查点的开发选模记录保留。

使用种子1301生成同一随机坐标排列：前128个为有序支持序列，后32个为独立查询集。每个历史伪目标均保留原标签，不按是否碰撞抽样。在支持8/16/32/64/128后评价同一32点查询集。两类场景各8条历史序列，共16条；这些是历史学习数据，不是新目标查询，也不计入有效搜索运行数。

为使可靠性得分与部署一致，完整重建每个支持标签到来前的模型：第i步只用前i个标签，从同一FSBO初始化重置并适配10步，学习率0.003；物理GP同样重置，10步、学习率0.01。缓存第0至128步的目标特征、核参数、均值和物理预测。后面的32个查询标签始终不进入适配或可靠性更新。

特征按完整512点批次计算，再提取160个所需位置，保持与完整候选推断的计算规则一致。核由缓存特征重建，须与原模型直接计算核数值核对。缓存绑定历史档案、基础检查点、源码和排列；完整项才可复用。新增物理调用为零，缓存和训练计算成本单独记录。

历史来源在历史坐标上的联合后验另存，不覆盖现有开发坐标缓存。来源构建仍只用该来源自己的历史碰撞和间距。每个伪目标须实际排除自身来源，不只是修改名称。

## 2. β选择与必要核对

预先比较`β∈{0,0.1,0.3,1,3}`；β=1为原幅度，β=0保留来源不确定性但关闭新增残差核。每个β分别完整重建支持序列的查询前概率，当前标签只用于随后更新。局部与全局权重共享同一组分量预测，但各自保留可靠性状态，不把拟合当前标签后的概率用于来源评分。

局部版本是预定主配置。β按该版本在全部8个历史伪目标、5个支持预算点的平均查询碰撞NLL选择，每类场景分别确定。先在历史谱系内平均，再等权汇总；同分依次比较Brier、与1的距离、β数值。记录全部β与全局权重结果，不从中挑另一版更好者替换主配置。

必须验证：

- 历史/开发角色隔离，自身来源排除，支持与查询集不相交。
- 第i步适配及可靠性只使用前i个支持标签；修改查询标签不改变缓存模型或前缀预测。
- 缓存核与直接核一致；分量概率由独立NumPy/SciPy Gaussian/Laplace推断核对。
- β=1恢复原形式，β=0关闭的只有来源残差项；目标分量不变。
- 来源排列不改变结果；局部及全局权重归一化，`κ=1`退化为全局更新。
- 16条前缀及全部β结果齐备后才选β；不把历史训练误差当作开发准入。

## 3. 后续开发验证

只有缓存及历史选择审计通过后，才登记新的在线矩阵。至少包括：学习β的局部主配置、相同β的全局权重、β=1的局部控制，以及同信息无来源FSBO＋物理GP。最后一项已有完整40项，可在信息、预算、初始化和实现一致并审计通过时复用；否则另行运行。

每个新增配置40项，保留512候选、128查询含8次初始化、环境81001和选例种子11/23/37/53/71。目标模型仍每次从原检查点重置并只用已付费碰撞适配；只给选择器公开参数、允许的历史先验与隔离查询接口。

在线主方法在运行前唯一指定，选β不读取开发发现结果。强参考纳入此前全部22个完成方法及本轮同信息目标控制。当前最高参考召回98.585721%，50%漏检减少所需召回99.292861%；同时要求平均碰撞数不降低、至少两个有碰撞的开发谱系正收益，并由同β全局及β=1控制支持主机制。基线若改变按同一公式重算，100%时不适用。置信区间、零碰撞库、去重及成本口径保持原方案。

本轮不能用历史参数学习或预测误差代替在线发现门槛。旧失败结论保持，C/D/E仍未进入；最终阶段仍须重训与最终核/权重一致的完整模型、补齐最近方法比较，并按原方案运行新交互任务、八个独立目标与严格留家族实验。

## 历史学习结果与预登记在线矩阵

16条前缀现已全部完成，64次独立适配重拟合及320项独立概率前缀核对通过；全部800项历史参数比较保存于[历史学习结果](../results/benchmark/collision/discovery/residual_scale/report.md)。预定局部配置选择切入β=0.3、切出β=1.0。切入NLL为0.244318，相对β=1的0.247719略降；切出保留原幅度。这里没有得到新的开发碰撞发现结果。

在线验证固定如下6个方法，每个40项，共240项：

| 方法 | 来源/目标模型 | β | 来源可靠性 |
|---|---|---|---|
| residual_local（唯一主配置） | 8个历史联合后验＋FSBO独立目标 | 历史选定0.3/1.0 | 局部0.30 |
| residual_global | 完全相同 | 完全相同 | 全局 |
| residual_unit_local | 完全相同 | 固定1 | 局部0.30 |
| residual_unit_global | 完全相同 | 固定1 | 全局 |
| residual_target | 仅FSBO目标GP | 不适用 | 单分量 |
| residual_dual_target | FSBO与联合教师各自只适配目标标签，不接收显式来源后验 | 不适用 | 局部0.30 |

全部方法外层均固定0.10物理GP。双教师控制的学习组中，联合教师0.75、FSBO0.25，与主方法的历史组及独立目标质量对应；两者均用查询前碰撞似然更新。该控制与主方法取得相同两套历史训练信息，避免将历史间距辅助训练或多表示集成的差异单独解释为来源后验收益。每个目标模型均从其原检查点重置，只对已付费碰撞适配10步；双教师控制允许两套目标适配，额外计算单独计费。

强参考固定为此前22个预登记方法加本轮两个目标控制。仍按最高平均召回、数量、AUC和方法名确定参考。主方法须达到50%漏检减少、数量不降低和至少两个正收益谱系，并满足：相同β的局部可靠性在召回上严格优于全局、数量不降；相对两个β=1控制，数量及召回不降；相对双教师同信息控制，召回严格提高、数量不降。β仅作为历史学习的模型设置，不预先将其本身列为独立原创贡献。若只有AUC等辅助变化，按对照如实解释，不替换128次主门槛。

切出β=1时，两个局部来源版本及两个全局来源版本分别具有相同算法参数，结果不能视为独立机制证据，须核对这些相同配置的行为一致性。全部单元、隔离查询、首项实际运行及独立数值核对通过后才运行其余矩阵。在线入口现已实现，历史学习结束不自动等于进入C/D/E。

补充独立入口`python -B -m benchmark.discovery_residual_selection_audit`已重算全部参数选择，核对16个不重复缓存任务、800个不重复比较、全部自身来源排除和320个概率前缀。所选β的独立概率最大差7.52e-12以下；整个网格最大差4.56e-7，原逐点验证使用绝对2e-7及相对2e-6容差。缓存工作进程耗时合计1,504.09秒，不解释为并行经过时间；参数比较耗时207.81秒。核查证据绑定选择结果、缓存索引、适配审计和概率检查的文件身份。

完整在线设计已保存至`residual_scale/online_design.json`，主配置、两个目标控制和各项进入条件在运行之前固定。当前有效搜索仍为1,720项、220,160次等效查询，本轮历史学习没有新增目标选择查询或物理调用。

## 在线实现、检查与实际运行顺序

选择器位于`methods/gcrt/residual_search.py`，完整矩阵与门槛位于`benchmark/discovery_residual_online.py`。方法只读取公开场景特征、历史分类后验、两个允许的基础模型及已付费碰撞标签；旧`QueryFeedback`、驾驶系统、场景库和冻结源码不修改。双教师控制分别适配两个已有模型，源版本仅适配FSBO目标模型；模型重置、适配和查询前评分均与方案一致。

38项相关检查已通过，覆盖六种方法、初始化计费、仅拟合已付费标签、来源排列、固定物理质量、单目标退化、双教师信息配置、侧面安全量不影响选例、进程隔离，以及门槛的完整配对、分母、预算、零碰撞和100%参考。全工程与MetaDrive回归在首项实际运行前执行，结果保存至`residual_online/regression.xml`。

依次使用：

```powershell
python -B -m benchmark.discovery_residual_online freeze
python -B -m benchmark.discovery_residual_online smoke
python -B -m benchmark.discovery_residual_online_audit smoke
python -B -m benchmark.discovery_residual_online_negative_controls
python -B -m benchmark.discovery_residual_online run
python -B -m benchmark.discovery_residual_online audit

```

`smoke`为第一项固定开发任务分别运行全部6种方法，各128次查询，这6项属于240项，不重复扩大样本。独立审计从原完整执行库重算去重分母、全部反馈、128点曲线及预算点；逐次重建来源可靠性，在查询9/65/128之前重新适配模型并用独立NumPy/SciPy推断核对完整512点选点。损坏控制在内存中修改标签、分母、重复查询、尺度、先验、评分、账本用途及两类内部自洽的错误概率，原文件不改写；至少8项被拒绝且6项正控制通过，`run`才允许启动完整矩阵。

运行保存在`results/gcrt/collision/discovery/residual_online/runs/`，协议、审计、门槛、PNG/SVG/PDF曲线、预算点区间及分项成本位于`results/benchmark/collision/discovery/residual_online/`。增量验收入口`python -B -m benchmark.discovery_residual_online_audit available`只检查已完整保存的项，不宣称整组完成。审计缓存绑定原始反馈、运行、协议和审计依赖，发生变化时重新计算。

全量审计还核对40对参数相同的切出发现曲线，不把相同配置复制当作机制收益；若曲线不同，先诊断数值重复性，不据此宣称尺度改善。最终报告要求全部240项与720次独立完整候选选点检查通过后才生成，按预算分别选择24个强参考中的最强者。失败尝试保留完整付费账本并单列成本，旧失败结论与C/D/E状态不改写。
