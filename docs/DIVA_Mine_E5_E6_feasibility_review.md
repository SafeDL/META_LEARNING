# DIVA-Mine：E5/E6 后的可行性复核与技术路线反思

复核日期：2026-09-13  
仓库快照：`SafeDL/META_LEARNING@f00943d7e921f6213b68f2e50f6357b2ad6413d5`  
依据：仓库代码、E5/E6 JSON、当前测试代码，以及用户提供的研究动机、技术方案、可行性调研三份 PDF。

**核验范围：这是源码与已提交结果的复核，没有在用户本地环境重新执行仿真，也没有完成修复后重跑。**

## 1. 核心判断

当前需要调整的不是 Transformer 大小，而是“诊断为什么值得付出测试成本”这一研究前提。

现有证据不足以维持“面对新 SUT，固定先做 4 次诊断，就能在总预算 20 内比共享风险先验发现更多危险”的主张。当前保存的数据中，共享先验已经接近真实得分上限。不过，E6 的双模式实现还有一处关键动作覆盖问题，不能把这次结果直接解释为“真实执行两类不同失效机制后，仍然证明个性化没有价值”。

因此，两件事应当分开：

- 当前方法在当前保存数据上没有达到固定预算收益目标，这是真实的负结果。
- 更广泛的历史 SUT 先验与少样本辨识方向并未被这些结果普遍否定；但它的正向可行性同样没有被证明。

## 2. E6 的“切入后制动”没有按代码意图传到低层动作

在 `mvr/highway/envs/cutin_env.py` 中，`ScheduledCutInVehicle` 继承 `ControlledVehicle`。其 `act()` 在制动窗口内设置 `acceleration = -self.braking_deceleration`，随后调用 `super().act(action)`。

仓库固定依赖 `highway-env==1.9.1`。该版本的 `ControlledVehicle.act()` 不是直接提交低层加速度的接口：它处理高层指令，然后重新生成动作，将加速度设置为 `self.speed_control(self.target_speed)`。因此，传入的自定义制动加速度被覆盖。

按这条调用链，E6 原计划的 4.5 m/s²、持续 1 s 的制动并没有直接施加到车辆。修复方向是把已经计算好的低层动作交给 `Vehicle.act(self, action)`，同时保留所需的碰撞、跟路与控制约束。是否真的产生预期减速，还必须用实际动作和速度轨迹验收。

另外，`cutin_duration` 当前用于改变 `KP_LATERAL = 2.0 / cutin_duration`。它是控制器参数，不是“车辆一定在 0.45 s 或 1.5 s 内完成切入”的轨迹保证。实际侵入时间、跨线时间和完成时间应分别记录。

目前双模式测试只断言数量平衡、仿真可运行、vulnerability 在 [0,1]，没有断言实际制动、速度下降或实际切入时长。因此 `10 passed` 不能证明两种实验机制已经按预期实现。

**解释边界：此问题使 E6 的双机制反证不完整，但不意味着修复后 DIVA 一定会获胜。**

## 3. E5 的 Oracle 需要改名和限缩解释

### 3.1 Oracle K=4 是全信息贪心探针选择，不是真正的全局上限

`oracle_support_indices()` 对每个候选点，计算加入该点后的 posterior NDCG@10，再贪心选择当前最高分候选。

它有三个局限：

1. 贪心逐点选择不保证得到最优四点组合。
2. 优化 NDCG@10 不等于优化计入 support 成本后的 CriticalScore@20。
3. NDCG 大量平分时，按候选索引打破平局；这些探针的直接危险得分可能很低。

故 E5 只能说明“当前低秩模型下，这个使用全目标信息的贪心排序策略仍未产生收益”，不能严格确认“任何 support 选择方法都没有收益”。

### 3.2 Oracle latent 是最小二乘投影，不是排序最优解

`oracle_latent_prediction()` 使用全部 target 响应对固定 source basis 做最小二乘拟合。它最小化重构平方误差，而不是最大化 NDCG 或 CriticalScore。

它可以检查表达与重构能力，不能被直接称为危险发现的数学上限。

### 3.3 真正适合排除收益的上限

对固定 bank，将 target 的真实正式得分排序，取前 20 项求和：

`S_oracle(u) = sum(top20(true_critical_rewards[u]))`

在同一候选池、相同正式得分、20 个互不重复场景的条件下，这是任何策略（包括诊断策略）的得分上限。E6 的 `gate_zero()` 使用了这个正确的上限。

## 4. 当前 E6 数据能支持的最强结论

| SUT | Shared Prior Score@20 | 真实结果 Oracle@20 | 最大可增加得分 |
|---|---:|---:|---:|
| A | 19.5 | 20.0 | 0.5 |
| B | 13.0 | 14.0 | 1.0 |
| C | 20.0 | 20.0 | 0.0 |
| D | 19.5 | 20.0 | 0.5 |
| E | 17.0 | 17.0 | 0.0 |
| F | 20.0 | 20.0 | 0.0 |
| 平均 | 18.1667 | 18.5000 | 0.3333 |

由 JSON 数值计算，六个 SUT 的共享得分总和为 109，Oracle 总和为 111。按“先求平均，再计算相对增益”的口径，最大可能增益只有：

`(111 - 109) / 109 = 1.8349%`

所以在当前保存的 E6 bank 上：

- 原来的平均提升 5% 不可达到，更不用说 10%。
- 最多只有 3/6 SUT 存在严格正提升空间，4/6 严格获胜也不可达到。
- SUT-E 的 17 分也是 bank 内上限，不能用名义满分 20 判断还剩 3 分空间。
- 这是当前 bank、当前计分与当前预算下的结论，不是所有自动驾驶测试任务的结论。

## 5. 三份研究材料中需要补充的关键前提

研究动机与技术方案把重点放在“共享低维结构”“少量观测可辨识”“辨识促进危险发现”。可行性调研进一步把候选创新收窄为 historical-SUT population prior、无 target-specific proxy、极少诊断与固定预算挖掘。这是研究定位，而不是正向收益的实证保证。

### 5.1 低秩不等于诊断有价值

考虑一个反例：

`f_u(x) = a_u * g(x) + c_u, a_u > 0`

不同 SUT 的风险数值不同，响应矩阵至多由两个公共方向表达，但所有 SUT 的场景排序完全相同。即使准确辨识 a_u 和 c_u，也不会改变应选的前 20 个场景。

因此，解释方差高只能支持“历史响应容易压缩”，不能独立证明“新 SUT 需要被辨识”，也不能证明“4 个观测足以带来有效个性化”。

真正需要的条件是：历史系统之间既共享规律，又在有测试价值的场景选择上存在可由少量观测辨识的差异。

### 5.2 信息增益不等于决策收益

当前 diagnostic acquisition 实现的是 posterior variance 乘以到 0.75 的三角形边界权重，并非技术方案中完整的对数信息增益和概率边界项。更重要的是，即使严格实现原公式，辨识 latent 或失效边界也不保证改变 top-20 的实际收益。

一个探针必须改变后续“该测哪些场景”，而不只是改变 posterior 的数值或让不确定性下降。

### 5.3 固定四次诊断有机会成本

设 H 为真实 Oracle@20 相对共享策略的额外收益空间。对一个已选出的四点 support 集 D，设 S_best(D) 为“必须先测 D，再用真实结果挑选最好的剩余 16 点”的总分。定义：

`C(D) = S_oracle - S_best(D) >= 0`

则任何使用该 support 的实际方法都满足：

`S_DIVA - S_shared <= H - C(D)`

诊断成本不是固定损失 4 分，因为 support 也可能触发危险；真正的成本是它替代了哪些更有价值的测试。当前 bank 的 H 极小，固定诊断很容易得不偿失。

### 5.4 “个体脆弱性”与“累计碰撞分”不是同一个目标

目前正式奖励没有区分通用危险和目标特有危险，也没有仅凭分数保证事故可避免或失效机制不重复。如果共享库已经能选出足够多的共同危险场景，就可能在该目标下接近最优。

这不是 baseline 太强而需要削弱，而是它揭示了：当前计分任务可能不需要个性化。

不能事后删除共享方法擅长的场景或更换主指标，制造 DIVA 增益。若要转向可避免、非冗余或历史系统未暴露的目标特有失效，那是需要独立论证并冻结的新问题定义，旧实验的负结果仍须保留。

## 6. 对可行性的更新判断

| 层面 | 更新后的判断 |
|---|---|
| 工程实现：Highway-env、缓存、SVD、解析后验 | 低算力路线仍可保留；但环境语义需用轨迹测试验证 |
| 历史 SUT 风险知识可复用 | 当前共享先验的强结果支持这一点，范围限于现有场景池 |
| 固定 K=4 诊断提高原始 Score@20 | 当前没有正向证据，现存 E6 数据甚至排除了原先效应量 |
| 低秩/信息增益本身构成创新 | 不成立；它们是技术构件，创新需体现在新的决策价值和实证结果 |
| 增大模型、增加交互模式就能解决 | 没有证据，不应继续按这一思路投入 |
| 更广泛的少样本个性化失效发现 | 可研究但高度有条件，不能保证能在当前任务上成立 |

## 7. 下一步只值得做一次纠错性验证

### 第一步：修动作语义，先跑少量安全样例

选择能完整经历制动窗口、不会提前碰撞终止的场景。记录前车每个仿真步的实际加速度、速度和横向位置。验收实际制动约为 -4.5 m/s²，连续 1 s 的速度下降约为 4.5 m/s；同时检查同场景无制动版本没有该速度下降，并记录实际切入过程。

先完成这项机制验证，不立即生成更大的 bank。

### 第二步：在原 E6 设置下做一次修复性重跑

不改变六个 SUT、候选数量、参数域、随机采样方案、K/B 与正式评分。保留原 E6，建立带版本信息的新结果目录。只在确认未受修复影响且复现一致的情况下复用旧样本；否则重建原 6×128 规模，不扩充实验。

先算真实结果 Oracle 上限，不训练模型、不重做 Teacher。

### 第三步：依据修正后的上限决定是否结束当前分支

若仍不足以支持事先选定的实际收益目标，则结束“固定四次诊断提高原始 Score@20”的实验分支；不继续更换模式直到出现有利结果。

若出现足够空间，再在同一 bank 上比较现有共享先验、最高风险 support、随机 support 与 DIVA，support 仍计入 20 次预算。NDCG 是辅助证据，不应在 top-10 饱和时作为查看最终 Score@20 的硬前置门槛。

这些 SUT 已经参与多轮方案修改，应视为开发数据。任何后来出现的正向趋势，仍需一次不参与调试的独立 SUT/场景验证，才能支持泛化主张。

## 8. 建议保留的研究方向

不再预设“每个新 SUT 都值得先诊断四次”，而研究：

**历史 SUT 先验何时足够直接挖掘，何时目标反馈能改变后续场景选择，以及最多四次诊断能否产生超过机会成本的收益。**

这里 K=0 应是允许的合理选择。该修正不是已经验证的新算法，也不能仅凭增加一个停止判断就宣称创新。但它比“所有任务必须先诊断四次”更符合当前负结果揭示的实际问题。

最终需要保留的是“历史系统经验如何降低新系统测试成本”这一问题，而不是强行保住固定四次诊断、特定 latent 模型或 DIVA-Mine 的名字。

## 9. 对前期建议的纠正

- 将低秩结构视为 few-shot 挖掘可行性的充分证据，过于乐观。
- 将最小二乘 latent 和贪心 K-shot 策略称为得分上限，不够严谨。
- 建议双模式扩展之前，没有先核验实际动作是否执行，顺序不当。
- 把 NDCG 改善设为最终挖掘实验的硬前置条件，不符合主指标与辅助指标的区分。
- 10% 是先前建议的投入筛选阈值，不是普遍成立的科学边界；当前应报告真实可达上限，而非围绕阈值是否通过争论。

## 10. 动作语义纠正后的执行记录

本复核提出的纠错步骤已在 `highway-env==1.9.1` 上完成。`ScheduledCutInVehicle`
不再调用会重新生成纵向控制命令的 `ControlledVehicle.act()`；它先保留跟路和
车道控制，再将计算出的低层 `steering` 与 `acceleration` 交给
`Vehicle.act()`。因此在制动窗口内，`-4.5 m/s^2` 动作不再被目标速度控制器覆盖。

安全样例（SUT-A、初始间距 40 m、相对速度 0 m/s）记录了前车每个仿真步的
动作加速度、速度与横向位置。可执行验收结果为：20 个连续的 `-4.5 m/s^2`
采样点，持续 1.0 s，速度下降 4.5 m/s；同一场景无制动对照的该时间窗速度下降
为 0。轨迹还记录了实际切入过程：快速切入首次横向运动/跨中心线/进入目标车道
分别为 1.05/1.20/1.50 s，制动切入为 1.05/1.60/3.40 s。完整逐步记录见
`results/diva_highway/cutin_mvp_e6_action_fix/mechanism_validation.json`。

随后在不改变六个 SUT、128 个候选、参数域、Sobol 采样、A/B 协议或正式
Score@20 的前提下，重建了 6×128 的修复版 E6 bank；未训练模型，也未重做
Teacher。新目录为 `results/diva_highway/cutin_mvp_e6_action_fix/`，并在 Gate 0
JSON 中写入动作实现和 simulator 版本信息。

| SUT | Shared Score@20 | 真实结果 Oracle@20 | 最大相对提升 |
|---|---:|---:|---:|
| A | 19.5 | 20.0 | 2.564% |
| B | 13.0 | 14.0 | 7.692% |
| C | 20.0 | 20.0 | 0.000% |
| D | 19.5 | 20.0 | 2.564% |
| E | 17.0 | 17.0 | 0.000% |
| F | 20.0 | 20.0 | 0.000% |
| 平均 | 18.1667 | 18.5000 | 1.835% |

修复后仍然没有任一 SUT 达到 10% 的 Oracle headroom，更不可能满足 4/6；此外
SUT-F 的失败率为 53.125%，超出原 E6 的 50% 难度上限。故按第 7 节第三步，
“固定四次诊断提高原始 Score@20”分支在动作语义已验收的条件下结束，不继续
更换 interaction mode，也不运行支持选择或 DIVA 的后续比较。这个结论是对当前
固定 bank、计分和预算的结论，不推广为少样本个性化的一般否定。
