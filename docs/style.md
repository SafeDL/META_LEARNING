# 编码规范

- 使用 Python 3，缩进为 4 个空格，遵循 PEP 8 的基本布局。
- GPU 环境运行在系统的: `conda activate metadrive`
- 导入顺序：标准库、第三方库、本项目模块。
- 命名：类用 `PascalCase`；函数、变量用 `snake_case`；常量用 `UPPER_CASE`。
- 不添加无必要的 CLI 参数；默认实验参数要写在脚本常量或配置文件中,从而使得代码可以直接运行。
- 鼓励代码简洁实现：优先使用直接可读的函数；不要为了兼容而引入复杂抽象或多层间接调用。
- 不保留废弃 wrapper、旧兼容分支、无意义 fallback、未使用字段、未使用配置、未使用函数和未使用脚本；发现后应直接删除，而不是继续转发或隐藏在兼容层后。
- 注释只解释不明显的设计或约束，避免重复代码含义。避免无意义的解释,不要造词,而是使用易懂简洁的用词
- 不使用空 `except`；错误应直接暴露或带有明确上下文。
- 不提交 `__pycache__`、大型可再生成结果和临时文件。
- 在不破坏现有功能和配置的前提下，删除冗余代码、重复逻辑、无用接口和临时缓存。
- 提升代码的可读性，尽量减少无意义的符号指代和专业黑话
- 非必要不执行防御性编程，非必要不执行哈希,清理实验性产物，注意文件和文件夹命名不要使用数字等在内的版本号
- 严禁超前设计，严禁过度工程，严禁防御未出现的错误，严禁向后兼容，严禁使用 胶水代码 掩盖需要修剪的实现和旧路径
- 每个目录至多保留一个 `README.md`；将该目录的职责、入口和结果索引合并在这一个文件中，不再创建重复 README 或 README 变体。
- 新方法设计、改进方案、理论与待执行实验统一维护在 `docs/method.md`；README 保留当前实现、运行说明和该文档链接，不另写方案摘要或维护平行版本。
- 方法目录允许采用已定义、含义明确的缩写，例如 `gcrt`、`lrt`、`dart`、`cg_brt`、`hgt`；首次介绍给出全称，代码、结果和测试目录统一命名。
- 本文方法位于 `methods/gcrt/`；具名对比方法统一位于 `methods/baselines/`；共享方法组件位于 `methods/common/`。实验设置和反馈接口位于 `benchmark/`，仿真环境位于 `simulation/`，驾驶控制器位于 `controllers/`。实测数据位于 `data/`，实验产物按 `results/gcrt/`、`results/baselines/`、`results/benchmark/` 分类；测试按相同职责组织。原始快照保留归档时的路径。
- 完整方法必须提供从历史响应数据开始的构建入口，明确基础核、历史编码器和当前方法所需收益网络的训练顺序；共享组件直接复用源码，不把预训练权重或旧实验快照作为方法定义的一部分。
- 论文与交流表达遵循根目录 README 的“论文与交流规范”：使用标准术语和明确方法名，避免口头禅、临时造词、过度严苛和防御性叙事。
- 中文方法标题和技术解释使用中文术语；英文名称与缩写集中说明。清理时保留有效的基线、回归测试、训练标签和正式结果，只删除确认无用的内容。
