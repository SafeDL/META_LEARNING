# 编码规范

- 使用 Python 3，缩进为 4 个空格，遵循 PEP 8 的基本布局。
- Python 格式、导入顺序和静态检查统一使用根目录 `ruff.toml`；检查命令为 `uv tool run --from ruff ruff check .`，格式化命令为 `uv tool run --from ruff ruff format .`。
- 导入顺序：标准库、第三方库、本项目模块。
- 命名：类用 `PascalCase`；函数、变量用 `snake_case`；常量用 `UPPER_CASE`。
- 不添加无必要的 CLI 参数；默认实验参数要写在脚本常量或配置文件中,从而使得代码可以直接运行。
- 鼓励代码简洁实现：优先使用直接可读的函数；不要为了兼容而引入复杂抽象或多层间接调用。
- 不保留废弃 wrapper、旧兼容分支、无意义 fallback、未使用字段、未使用配置、未使用函数和未使用脚本；发现后应直接删除，而不是继续转发或隐藏在兼容层后。
- 注释只解释不明显的设计或约束，避免重复代码含义。避免无意义的解释,不要造词,而是使用易懂简洁的用词
- 不使用空 `except`；错误应直接暴露或带有明确上下文。
- 不提交 `__pycache__`、大型可再生成结果和临时文件。
- 在不破坏现有功能和配置的前提下，删除冗余代码、重复逻辑、无用接口和临时缓存。
- 提升代码的可读性，尽量减少无意义的符号指代和专业黑话
- 非必要不执行防御性编程，非必要不执行哈希,清理实验性产物，注意文件和文件夹命名不要使用数字等在内的版本号
- 严禁超前设计，严禁过度工程，严禁防御未出现的错误，严禁向后兼容，严禁使用 胶水代码 掩盖需要修剪的实现和旧路径
- 每个目录至多保留一个 `README.md`；将该目录的职责、入口和结果索引合并在这一个文件中，不再创建重复 README 或 README 变体。
- 根目录 `README.md` 只保留必要的安装、检查和使用指导。程序结构由各目录 README 说明，实验设置与评价口径集中在 `experiments/README.md`，结果索引放在 `experiment_outputs/README.md`；已冻结的实验配置和历史验收记录保留原样。
- 完整方法必须提供从历史响应数据开始的构建入口，明确基础核、历史响应编码器及碰撞监督模型的训练顺序；共享组件直接复用源码，不把预训练权重或旧实验快照作为方法定义的一部分。
- 论文与交流表达遵循本文的“研究与写作约定”：使用标准术语和明确方法名，避免口头禅、临时造词、过度严苛和防御性叙事。
- 中文方法标题和技术解释使用中文术语；英文名称与缩写集中说明。清理时保留有效的基线、回归测试、训练标签和正式结果，只删除确认无用的内容。
- MetaDrive 是工程内保留的独立仿真平台。清理时保留 `controllers/metadrive/` 和 `simulator/metadrive/` 的源码、配置、运行脚本及有效测试，不能因其未进入 HighwayEnv 主实验而移除或移出工程。
- 当前目录命名统一为 `experiments/`、`simulator/` 和 `testing_methods/history_transfer/`。`test_records/` 保存仿真测试产生的原始记录及汇总档案，`experiment_outputs/` 保存方法模型、选例过程和统计分析结果；冻结记录中的旧路径和 `gcrt` 标识保留，不能据此重新使用已移除的源码包名。
- `testing_methods/baselines/` 保存自动驾驶失效测试的基线方法及其训练、搜索和复现说明；共享模型与训练组件放在 `testing_methods/common/`，驾驶控制器放在 `controllers/`，回归测试放在 `tests/`。
- 本文的实验维护范围为独立验证、方法定型开发比较及其数据、模型、基线、成本和审计依赖。已替代设计的专属实现、测试和结果应一并移除；同一保留实验中的运行按既定任务完整保留，不按结果正负或显著性删选。冻结协议不因源码清理而改写，原登记源码与维护源码分开核对。

## 研究与写作约定

全文围绕**自动驾驶失效测试、有限预算下的失效发现效率、系统间测试经验迁移和交通场景机制**组织。成熟机器学习方法可以通过解决这一领域特有的问题形成有价值的方法贡献；不要求另行发明通用机器学习算法，也不存在采用某算法就必须在其原始任务上超过它的普遍要求。

主线是历史驾驶系统响应提供危险区域线索，目标反馈修正其适用性，再以预算内碰撞发现和具体驾驶交互解释方法价值。核心证据围绕整体测试效率、严格留家族迁移，以及历史信息与目标反馈的联合作用组织。

先解释具体驾驶问题、测试方法如何起作用，再用发现效率、系统间迁移和场景交互说明研究价值。使用标准中文术语，英文方法名与缩写在首次出现时说明；所用方法基础按实际使用引用。详细实验过程放在结果记录中，论文围绕研究问题、方法和证据组织。

论文以整体测试效果和跨系统迁移价值为主，组件消融用于说明贡献方向。组件带来正收益即可作为保留依据，不把每个组件都达到明显增益或统计显著作为继续研究或完成论文的必要条件。组件收益可能受到所选被测自动驾驶系统（ADS）和实验设置影响，结合后续实验结果解释。

## 文献阅读与复现要求

用户提供的[Google Drive全文目录](https://drive.google.com/drive/folders/1iwBbWzrkb-1LN9ZmjfO2oSheXCtXX78j)是优先来源。具体实现每个具名方法前，应阅读完整的方法、公式、伪代码、实验配置和相关附录，并核对作者代码；不能只根据摘要或方法名称写近似版本。

每个方法目录的 README 记录论文章节、算法步骤与实现函数的对应关系、超参数、数据用途和可运行入口。场景输入、风险反馈、有限候选库等任务适配单独说明，保留原算法的主要机制。已有 SAMOTA 和 Indago 也按同一要求核对，再进入新的配对实验。
