# RGPE碰撞分类的独立开发比较

本比较补齐[方法定位](collision_discovery_method_positioning.md)中最接近的外部集成方法。当前残差尺度主配置已失败，本比较保留该结论，用于检验来源可靠性与普通排序集成的区别，不将外部基线重新指定为本文主方法，也不自动启动C/D/E。

## 比较对象与固定规模

| 设置 | 内容 |
|---|---|
| 方法 | `rgpe_classifier`；`physical_rgpe_classifier` |
| 来源 | 同一8个历史系统的固定碰撞潜在后验，包含相同历史间距辅助训练信息 |
| 目标表示 | 同一FSBO基础模型，每次重置后只用已查询碰撞适配10步，Adam学习率0.003 |
| 任务 | 4个现有开发系统×切入/切出×5个配对种子，共40项/方法 |
| 候选与预算 | 512个公开候选，128次查询，包含8次共同随机初始化 |
| 种子 | 选例11、23、37、53、71；环境81001 |
| 有效运行 | 共80项、10,240次等效查询；两个实际首项计入80项 |
| 原始数据 | 复用已有完整执行档案，不新增物理调用或正式目标记录 |
| 参考集合 | 原22个完成方法＋残差尺度6个完成方法，共28个；须等待当前240项完整结束并独立审计 |

RGPE按2018年原始版本的来源GP/目标GP排序投票实现，保留目标优先同分和中位数超过目标95%分位的剪枝。目标留一折只移除该折标签，固定在全部已查询标签上适配后的核、表示及均值，再独立求解该折潜在后验；不称为留一重训全部超参数。GP集成使用平方权重合并方差，再积分得到碰撞概率。

二元标签只比较不同类别的有序对；没有不同类别的已查询对时按目标优先规则使用目标GP。每次固定512个独立高斯样本，不同来源及不同留一折独立，同一折内保留位置间协方差。抽样种子为选例种子加`1009×已查询数`，按来源标识固定顺序。共享FSBO表示、Bernoulli/Laplace、标签对规则和碰撞概率贪心均是本项目的任务改编，不表述为原连续贝叶斯优化实验的原样复现。

第二个版本在上述GP集成的碰撞概率外，固定混合0.10物理GP概率。物理GP也只用已查询碰撞，每次重置并适配10步Adam，学习率0.01。这是本项目的匹配控制，用于区分普通物理分量的作用。完整定义和原文链接见[实现说明](../methods/baselines/rgpe/README.md)。

## 前置检查和阶段顺序

已完成15项专门检查及相关既有回归。历史数值核查覆盖全部8个历史伪目标、两个场景、8和128个支持点，共32组完整512点预测；每项排除伪目标自身来源。1,728个有排序信息的留一模式经独立NumPy/SciPy核对，全部有限蒙特卡洛权重及剪枝一致，最大完整库概率差为1.63e-10。其余单类标签项保留，按目标优先退化。这里只共享标准正态/均匀随机数，GP推断、损失、剪枝、投票与积分独立计算。基础教师包含全部历史对象，不能将该检查称为独立留系统验证。

`prepare`先登记方法、任务、参考、源码和准备证据；它不运行开发查询。当前240项结束并经完整审计后，`freeze`再核对全部28个参考、预算和分母，并拒绝与登记设计不同的实现。此前不运行新开发比较。

```powershell
python -B -m benchmark.discovery_rgpe prepare
python -B -m benchmark.discovery_rgpe freeze
python -B -m benchmark.discovery_rgpe smoke
python -B -m benchmark.discovery_rgpe_audit smoke
python -B -m benchmark.discovery_rgpe_audit negative
python -B -m benchmark.discovery_rgpe run
python -B -m benchmark.discovery_rgpe_audit complete
python -B -m benchmark.discovery_rgpe report
```

独立历史核查入口为`python -B -m benchmark.discovery_rgpe_audit historical`，其32项检查已经完成，不在登记之后重新写入证据。新增代码及准备证据在实际冻结后保持一致。审计器变动须重新验证；逐项缓存绑定审计依赖、运行、协议与原始反馈，不能复用过期结果。

首项为两个方法分别执行同一个固定任务，各128次查询。两项真实反馈、完整分母、账本和六次完整候选选点独立核对通过，并且至少八项内存损坏记录被拒绝后，才允许运行80项矩阵。损坏检查不改原文件，不新增选择查询。

## 审计范围和输出

所有128条反馈都与原始完整执行逐条匹配；核对初始化计费、唯一查询、去重碰撞分母、曲线及预算点。每步检查权重归一、512次投票的整数质量、剪枝与损失摘要、已查询不同标签对数、概率混合和计时；在查询9、65、128之前重新适配目标模型，用独立NumPy/SciPy推断重建完整512点概率、来源权重和实际选点。逐步摘要检查不等于每步均独立重算了全部GP与蒙特卡洛样本，报告分别列出覆盖范围。

选择器通过隔离查询接口取得实际碰撞Boolean，不读取全库标签、召回分母或未查询轨迹。历史来源的构建和排除由评估端核对。80项结束及240次完整候选选点审计通过后才生成整组报告；不完整或重复任务、预算/分母不一致都拒绝汇总。

输出位置：

- 准备检查：`results/baselines/rgpe/collision/preparation/`。
- 80项运行：`results/baselines/rgpe/collision/discovery/runs/`。
- 登记、冻结、索引、独立审计、失败账本和报告：`results/benchmark/collision/discovery/rgpe/`。

报告先按谱系内平均，再对谱系等权平均，使用配对分层自助法2,000次、种子1501。数量、召回、16/32/64/128预算点和完整曲线同时报告，数量与召回不解释成独立证据。零碰撞任务保留，召回不适用。对两个新方法分别比较最强既有参考，并比较有无物理分量；报告全部方法，不按结果替换比较对象。历史建设、已有教师训练、准备检查、模型加载、来源构建、留一选例、目标/物理适配、回放等效仿真和失败尝试分别计费，工作进程耗时不当作并行经过时间。

本比较不能补足尚未执行的新交互场景、八个独立目标、严格留家族或最终一致性重训。所有完成方法纳入后续强参考；阶段B的旧主方法及失败结论保持。ScaML-GP分类协议及同推断目标控制已另行登记，仍待完整运行和验收；层次GP尚未实施，不能把内部消融直接计为具名外部方法的结果。

## 当前执行与资源调度

240项残差实验、完整独立审计与报告已完成。RGPE已冻结并完成两项实际首轮，各128次查询；6次完整候选选点审计通过，8项损坏控制被拒绝。随后启动80项完整比较，首轮两项复用，不重复扩大矩阵。ScaML四模式160项已经另行登记，继续等待RGPE完整审计及报告。

两个RGPE任务并行后的完成速度明显慢于单任务首轮。只使用元张量的算子跟踪确认，128点留一后验的512次联合抽样会在当前矩阵乘法广播中产生`[512,128,128,128]`的8 GiB临时张量，GPU观测显存接近24 GB上限。跟踪未执行大型真实分配，也未改变采样函数、种子、样本数或冻结源码，证据在`orchestration/sampling_shape_probe.json`。

短时调度探针及原进程恢复记录保留在`orchestration/`。最初在评估查询服务处错开一个任务，随后为释放已占用的GPU资源，结束一个已确认身份的选择器进程。评估工作进程保存了该项的完整失败账本，共97次已付费查询；这部分单列失败成本，不计入有效80项结果。原算法文件、初始化、种子、候选与已完成首轮结果不变。

恢复调度记录为`orchestration/resource_recovery.json`：先让其余任务继续，在至少78项有效记录完成或6小时上限后恢复被延后的评估工作进程，等待原运行明确结束；核实仅缺一项后，再使用原`run`入口复用79项完整结果，只补跑缺失项，然后执行完整独立审计与报告。重新运行的模型从原历史初始化开始，不能读取中断任务的反馈；恢复器还记录其前缀是否与保存的97项账本完全一致。

原ScaML等待队列在任何实际查询前被替换为依赖该恢复流水线的同一登记设计，仍须RGPE80项、完整审计及报告全部通过才允许冻结、实际首轮及后续160项。任一步失败即停止。暂停等待、失败尝试和重试均计入实际经过时间，不能把共享GPU及暂停时的耗时当作算法独占GPU的耗时。当前8 GiB复制属于本实现的计算开销，不代表RGPE的理论内存下界，也不据此主张本文方法有计算优势。

另对保存的失败前缀作独立计费核对，见`audit/failed_prefix.json`：97个唯一付费坐标及反馈均与完整执行档案一致，前8项初始化、冻结任务/协议、历史上下文和执行合同均匹配。经过时间2,832.80秒、查询服务计时0.279853秒，所引用原执行的等效仿真耗时2.743530秒；三者含义不同，新增物理调用为零。该核对只证明失败账本和计费信息，不重建已终止选择器的逐步GP概率，也不把97项补成有效128次运行。

运行期间已用`python -B -m benchmark.discovery_rgpe_audit available`复核当时完整保存的52项：6,656条反馈、预算/分母及逐步摘要一致，156次独立全库概率、来源投票与实际选点核对通过。复用2份首轮审计，新增50份绑定源码/协议/运行/原始反馈身份的逐项记录；这些记录可供最终80项审计复用。当前只完成`available`范围，`whole_matrix_audited=false`，不代表80项完成、准入通过或整组报告可发布。

该批增量审计到结果落盘经过247.32秒，新增50项工作进程核对耗时合计460.72秒；与选择器共享GPU，不能当作独占算法计时。重叠区间、进程身份与成本范围保存在`orchestration/available_audit.json`。未改变算法、登记协议、种子、候选或查询权限，也未新增选例与物理调用。

## 完整比较结论

80项、10,240次等效查询现已全部完成，240次独立全库重建及全部反馈、预算、分母、投票摘要核对通过。恢复器在78项时释放延后工作进程，确认旧运行结束和79项完整缓存后，仅补跑原`development_idm_mobil/cut_in/37`缺失任务。重启的前97次选点、反馈、用途和账本身份与原失败前缀一致；原完整记录比较为false，仅因97项`wall_s`计时不同，见`audit/restarted_prefix.json`，不将计时差异写成选点不一致。

| 方法 | 平均去重碰撞数 | 平均召回率 | 发现曲线AUC |
|---|---:|---:|---:|
| RGPE分类 | 36.375 | 95.171525% | 22.797070 |
| RGPE分类＋物理GP | 36.725 | 96.436841% | 22.801172 |
| 最强既有参考`physical_local` | 37.875 | 98.585721% | 24.098828 |

两种RGPE分类改编没有提高当前最强参考。独立重算完整30种方法、1,200项配对记录的谱系汇总、完整曲线和16/32/64/128预算点，与报告一致；零碰撞任务保留。当前50%漏检减少要求仍为99.292861%召回，并有IDM/MOBIL与PPO两个谱系存在理论提升空间，见`report_checks.json`及`feasibility/after_rgpe.json`。门槛不表示统计显著性，后续仍纳入全部新强参考重新计算。

完整结果、配对分层区间和分项成本见[报告](../results/benchmark/collision/discovery/rgpe/report.md)及`report.json`。97次失败查询仍单列成本，新增物理调用为零。ScaML已按登记协议冻结并进入四项实际首轮；新收敛推断搜索继续等待该160项的完整审计与报告，不自动进入C/D/E。
