# 虚拟反馈中的目标核适配：历史诊断

## 待检验问题

现有碰撞搜索在每次实际反馈后，从同一历史初始化重新拟合10步目标深核，并重新拟合物理GP。标准的低成本虚拟反馈通常固定这些参数，只对新增标签条件化。若两种更新会明显改变后续排序，前瞻收益估计就需要单独核对这一近似。

本诊断使用16个历史伪目标，不新增开发搜索或物理执行。既有240项失败结论、RGPE80项与ScaML160项设计保持原样；阶段C的正式160项比较仍未进入。一次虚拟反馈加后续批量收益沿用[ENS（ICML 2017）](https://proceedings.mlr.press/v70/jiang17d.html)构造，不将其列为新的原创机制。本项不修改原阶段门槛，也不将少量候选间的比较称为完整选例实验。

## 固定输入与对照

每个历史系统在切入、切出各作为一次伪目标，自身从来源上下文排除。基础教师曾用全部历史对象，本项用于历史机制诊断，不能称为严格留系统验证。复用种子1301序列前64个支持点；另外7个来源后验、历史选定β、局部带宽0.30、0.75/0.25来源/目标先验、外层0.10物理质量与当前残差主配置相同。

根据64点反馈后的查询前预测，从其余448个候选选两个不同候选：碰撞概率最高者；排除前者后Bernoulli熵最高者。选择只用预测及场景标识，同分规则沿用现有约定，不读取候选的真实标签。

分别假设两个候选反馈为0、1。三个对照共享同一次虚拟标签以及用查询前分量概率更新的局部来源可靠性：

| 对照 | 目标深核 | 物理GP | 标签条件化 |
|---|---|---|---|
| 固定参数 | 保持64点时参数 | 保持64点时参数 | 65点 |
| 重拟合目标 | 从历史初始化重拟合10步、0.003 | 保持64点时参数 | 65点 |
| 完整重拟合 | 同上 | 从初始状态重拟合10步、0.01 | 65点 |

来源历史后验保持不变，虚拟更新不得改动实际模型、既存权重或历史缓存。每个候选的两个分支只在标签条件化和重拟合中使用对应虚拟标签；来源可靠性禁止用拟合该标签后的概率重新评分。

## 比较范围与规模

共`16任务×2候选×2虚拟标签×3对照=192`组全512点预测。目标/物理重拟合在同一分支内复用，避免重复计费。逐组用独立NumPy/SciPy推断核对两种目标模型的全部来源分量，以及两种物理模型；共128组分量概率、128组物理概率和192组混合概率。

在`h=5`及`h=64`比较一次虚拟反馈加后续最高`h−1`项批量预测收益。64包含即将选择的当前查询，已付费64点及当前候选不进入后续批量。只比较上述两个预定候选之间的收益排序，不声称已经对448个候选完成前瞻最优化。

两个候选的收益差绝对值不超过1e-8时按同分处理。只有固定参数和完整重拟合两者的收益差均超过该数值容差、且偏好相反时，才计为明确的候选偏好改变。

评估端另外读取历史档案中的实际标签，记录实际分支的剩余库NLL/Brier，以及该分支一次查询后固定批量所包含的真实碰撞数。这是历史批量潜力诊断，不是128次自适应搜索的碰撞数量或召回率。先在历史谱系内汇总，再等权平均。保留零碰撞历史任务和全部两个虚拟分支。

结果只回答近似更新是否改变预测、候选比较和成本。即使完整重拟合的批量潜力更好，也须另行登记可执行的完整选例策略、同信息对照及原50%漏检减少要求，才能验证开发发现收益；不自动进入后续阶段。

独立推断核对复现当前的10步Laplace规则。解释虚拟分支的排序差异之前，还需检查模式残差，区分目标核适配与有限迭代误差；数值实现一致本身不等于每个虚拟模式都已收敛。

## 执行与产物

`python -B -m benchmark.discovery_counterfactual_adaptation prepare`登记配置，`run`执行历史诊断。输出位于`results/benchmark/collision/discovery/counterfactual_adaptation/`。原缓存、在线结果和正式目标保持各自既定状态。验收还包括：64点模型与已有缓存一致、真实状态不变、历史自身来源排除、虚拟可靠性更新一致、剩余预算边界及原协议一致性。记录重拟合、预测、独立核对和总耗时；不将共享机器上的耗时当作独占运行成本。

## 执行前的设备核对

首次诊断采用CPU重拟合，在首历史任务的特征坐标核对处停止，尚未计算虚拟分支。随后对全部16个历史任务核对，10项的CPU重拟合核与已有CUDA缓存不在原数值容差内。部分差异只是深核坐标的平移，但不能用该解释涵盖其余任务。失败、原登记及源码保存于`failed_attempts.jsonl`、`failed_cpu_prefix/`，完整探针见`device_equivalence_probe.json`。

修正为与当前在线方法、历史适配缓存相同的CUDA重拟合；独立NumPy/SciPy推断仍在CPU执行。原特征、核参数、预测和已有评分的数值容差不变。新增CUDA状态不变及反馈范围检查，GPU计时在阶段边界同步；与正在运行的RGPE共享GPU资源，分别记录该影响。该修正不改目标、候选、虚拟标签、模型更新或结果筛查规则。

## 已完成的预测与批量诊断

16项历史任务、192组全512点预测现已完成。128组分量、128组物理概率和192组混合概率独立核对通过，最大差分别3.32e-14、4.45e-16和6.94e-15；16个原64点模型与缓存核的最大差5.51e-14，既有查询集损失最大差8.33e-17，真实模型及来源状态不变。独立复核还从保存的数组重算了32次候选选择和192项收益/实际分支批量记录，见`summary_audit.json`。

完整重拟合在32项两个候选/窗口比较中改变4项明确偏好，均发生于64步窗口；这4项在仅重拟合目标深核时已经出现。5步窗口的偏好未改变。按各自预测收益在两个候选中作选择后，完整重拟合相对固定参数的实际分支批量碰撞潜力，切入平均少0.375个、切出多0.250个；两个场景等权平均少0.0625个，5步窗口均无变化。这是历史固定批量诊断，没有构成稳定的发现收益。

这些结果说明固定参数近似会影响部分候选比较，但不支持仅以预测收益增加为由启动完整目标重拟合前瞻。模式残差检查仍待完成，当前不能将差异全部归因于核适配，也不能把本项视为阶段C或128次发现门槛通过。结果与完整比较见[报告](../results/benchmark/collision/discovery/counterfactual_adaptation/report.md)。

本轮GPU诊断经过时间2,409.17秒，包含与RGPE的显存争用，不能外推为独占运行时间。原CPU失败及设备探针另列成本；没有新增开发选例或物理调用。

## 模式收敛的独立审计

另行登记`benchmark.discovery_counterfactual_mode_audit`，不改原192组预测。审计对10步迭代的结果计算白化坐标梯度，最大绝对值不超过1e-6时记为满足本次数值审计容差；超出时调用独立的收敛模式求解，记录概率差。该容差是数值诊断标准，不是方法发现收益或概率校准保证。

先执行CPU缓存审计，检查全部16个64点实际前缀、所有物理分支，以及候选坐标落在原160点特征缓存中的固定目标核分支；其余候选明确列为未覆盖。全量审计按原CUDA后端重新拟合64/65点目标模型，覆盖1,296个单分量模式并核对192组保存的全512点预测；等待RGPE80项完整审计及报告后再启动，避免与大广播采样同时占用GPU。部分缓存通过不能替代全量审计。

```powershell
python -B -m benchmark.discovery_counterfactual_mode_audit prepare
python -B -m benchmark.discovery_counterfactual_mode_audit cached
python -B -m benchmark.discovery_counterfactual_mode_audit full
```

审计登记、缓存及全量结果位于`counterfactual_adaptation/mode_audit/`。保留原输入证据及源码身份，审计本身不新增开发查询或物理执行。

缓存子集的368项模式审计已完成：18项超过1e-6，其中6项来自真实64点历史前缀，12项来自缓存覆盖的固定核虚拟分支，均属于历史来源分量。最大白化梯度122.4167，收敛求解的最大单分量概率差0.994820；这不是最终混合概率的同等差异，也不能证明前面4项偏好改变均由数值误差造成。完整1,296项模式及192组预测审计继续排队，当前不作全量通过结论。相同历史任务上的收敛修正与后续对照见[收敛来源推断方案](collision_discovery_converged_inference.md)。

## 完整模式审计结果

RGPE完整验收后，全量模式审计已完成，覆盖1,296个单分量和192组保存预测。独立覆盖与汇总核对通过：82个历史来源模式未达到1e-6容差，其中真实前缀6个、虚拟分支76个；最大梯度124.218864，最大单分量概率修正0.995307。独立目标和物理分量在该矩阵中均满足容差。原缓存368项的收敛分类与全量记录一致，原缓存文件保留不改。

原4项明确偏好改变中，非线性优化切入、线性MPC切出、UCT切出的所有受检模式均满足诊断容差，IDM/MOBIL切出含3个未收敛来源模式。故既不能把4项改变全部归因于数值误差，也不能把未重算的收敛混合及批量收益写成已证明的核适配收益。原实现的预测和实际分支批量统计保留；这项诊断没有通过阶段C或碰撞发现门槛。

全量经过45.97秒，未新增开发查询或物理调用；[完整模式报告](../results/benchmark/collision/discovery/counterfactual_adaptation/mode_audit/report.md)与`full.json`、`summary_audit.json`单独保存。已登记的收敛推断贪心比较和强基线保持原协议，C/D/E仍未进入。
