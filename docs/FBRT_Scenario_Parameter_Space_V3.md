## 定位与依据

本文件重新定义下一轮**开发候选**的逻辑场景空间，不改写 `research_v2` 冻结清单、已测响应或历史结论。具体场景需要给出全部轴值、固定上下文、种子和执行契约。ASAM OpenSCENARIO 将参数取值范围定义为逻辑场景，把选定参数后的实例定义为具体场景；范围可以通过离散步进、分布或随机设计取样，而不要求所有功能场景具有相同维数。[ASAM 场景抽象](https://openscenario.asam.net/ASAM_OpenSCENARIO_DSL/current_dsl_v2.x/conceptual-overview/scenario-abstraction.html)

选轴原则：轴必须改变初始冲突几何、相对运动、事件时序、制动强度或可用避让空间中的独立因素，并且要被当前物理执行器实际读取。前车停止、前车减速、同向换道属于不同的事故前场景类别，不能仅以统一的“间距×强度”替代。[NHTSA 事故前场景分类](https://www.nhtsa.gov/sites/nhtsa.gov/files/811731.pdf) 对切入测试，初始间隙、相对速度和换道过程是关键条件；但文献不能直接证明本仓库的数值上下界。[Zhao 等，IEEE T-ITS 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5103645/) 当前数值范围是基于原 `research_v2` 边界、现有三个物理上下文和 20 Hz/直路执行契约提出的**探索性测试范围**，不是自然驾驶分布、事故率或安全阈值的估计。

Highway-env 的 IDM 纵向控制依赖前车距离和相对速度；MOBIL 换道决策还依赖新车道前后车的制动影响。因此 S05、S09 需要同时描述前方需求与后方可用间隙。[Highway-env IDM/MOBIL 文档](https://highway-env.farama.org/main/dynamics/vehicle/behavior/)

## 实例化与验证门槛

V3 的八个已接线家族按维数分别取 3 维 1,024 点、4 维 2,048 点、5 维 4,096 点的 scrambled Sobol 样本，共 **19,456 个开发候选**。所有家族的任意两轴投影均占满归一化空间的 16×16 分箱；这只证明该分箱尺度的投影覆盖，不证明高维连续空间已充分覆盖。Sobol 点数是计算预算选择，不是文献给出的最优样本量。清单由 `python -m methods.failure_memory_regression.prepare_scenario_sampling` 生成；NL/PPO 可以共用物理参数清单，但执行和响应仍须分别完成。

FM²-FBT 以每个功能场景族为独立测试任务；`parameter_groups`、`research_bounds` 和 `active_parameters` 已随每个候选写入清单，供后续 schema-aware encoder 使用。本次只准备场景空间，没有训练或声称已经实现该编码器。

现有 `bidirectional.py` 的冻结器与若干前沿/连通分量指标依赖二维 `grid_index` 和四邻接；V3 候选**不能直接作为该评估协议的正式输入**。正式启用前需为变维采样设计新的冻结、邻域及覆盖定义，并对所有对照方法使用同一候选池。现有二维结果继续按原协议解释。

在冻结下一份确认协议前，应按场景族检查：每个轴改变时初始状态或脚本事件确实改变；不存在初始重叠、超出道路速度限制、事件未发生、后车无可达轨迹等失效组合；保留无法判定的条目并报告原因。S02 的静止目标在状态观测中可能提前可见。S04/S09 的功能恢复需有专门终点；只统计自车碰撞时，不可把它们表述为完整停车再起步或恢复能力验证。用于最终确认的取值范围、采样种子、资格过滤与终点须在读取目标版本结果前独立冻结。

预算截点改为5/10/20/30/50，全部来自同一条B=50查询序列的前缀。主指标D@50，同时报告Recall@50、HitRate@50；旧B=20结果仍按原协议解释，不补称为B=50结果。

每族 50 次查询分别占 3／4／5 维候选池约 4.88%／2.44%／1.22%。点数是开发计算选择，不是对连续逻辑空间的充分覆盖证明。若正式确认另定候选规模，必须在读取目标结果前冻结。

对每个SUT完整测量19,456个指定场景/随机实现可形成有限库参考真值。多方法重放同一银行不增加物理执行，但每次揭示仍计作该方法一次目标查询；完整建库成本、模型训练成本与部署查询成本分别报告。

无法判定执行照样计费，不能训练成PASS，也不能根据其目标结果事后从候选池删除。真实failure数为0时Recall=NA，任务仍保留。候选不足50时用实际次数报告，不能通过重复同一个候选补足50个发现。

## V3.1 新增条款二：变维schema不是不同长度的无名数字数组

每个字段需声明：

```text
parameter_name        规范语义名；不使用列号代替
actor_role            ego / lead / rear / static / other
semantic_group        geometry / speed / timing / braking / acceleration
value_type            continuous / categorical / boolean / fixed_context
unit                  转换后的统一单位
bounds                冻结的活动范围或上下文归一化尺度
value                 当前实例真实值
missing_state         present / missing / not_applicable
schema_version        与执行器和manifest绑定
```

`research_bounds`、`active_parameters`、`parameter_groups`来自用户附件声明的V3 manifest。实际字段键必须从用户本地YAML核对，不能仅按中文名称猜测拼写。

对一个3D场景，产生3个活动参数token；5D场景产生5个。每个token宽度固定128，另可附带固定上下文token。集合编码与池化得到固定128维场景表示。

这称为**支持不同参数数量的编码**，而不是维度没有意义。S06与S08的局部物理距离仍在各自3D、5D连续活动空间内计算。新参数语义从未出现在训练中时，不能仅靠同名embedding机制就宣称模型已经理解它。

允许batch padding，但所有padding必须mask。参数语义标签随数值一起移动；去掉位置编码后，改变JSON字段顺序不应改变最终预测。

旧 `active_values()` 的默认二维返回不能用于V3新路径。任何缺字段、单位冲突、固定上下文覆盖活动轴等问题都应报错或标记缺失，不可静默补成0.5。

## V3.1 新增条款三：历史失效记忆的schema对齐

历史记忆基元应保存：**适用条件、真实失败见证、同SUT通过对照、可观察事件描述、来源与证据支持**。

1. 仅在相同功能场景、执行契约与可解释的固定上下文中聚合局部证据。
2. 旧2D记录中的新轴若确实作为固定上下文被记录并实际执行，可以经过显式schema映射转为对应token；没有记录的值必须missing，不补造。
3. 失败／通过对照来自同一个历史SUT；不能拿不同历史系统的两个点宣称同系统边界。
4. 聚类中心不是完整机制。保留分散见证、成对差异及role/phase，不把不同碰撞模式因为接近而强制合并。
5. history-only模式与target在线失败记忆分开存储；目标完整结果不得进入跨源 occurrence 汇总。
6. “机制”是观测到的行为模式，不能未经因果分析标注“感知缺陷”等内部根因。
7. 无历史失败但有通过样本，保留pass-only覆盖摘要；完全没有兼容历史时才使用NO_HISTORY。

Transformer用于这些基元之间的关系建模和candidate相关检索，不创造历史证据，不进行无依据的安全推断。

## V3.1 新增条款四：候选检索、目标反馈与二臂路由

**Global**：对本族所有未查询候选计算失效分数，从中选一个。

**Local**：仅在当前target已经真实失败的seed邻域内，结合失效分数、距离与方向多样性选一个。邻域是V3 Sobol点的kNN，不再使用二维四邻接，不向全库外无计费生成点。

一次目标反馈同时用于：

- 将真实PASS/FAIL及有效执行摘要加入target support；
- 调整当前候选对历史基元的检索权重；
- 有真实failure时登记新的target seed；
- 更新本次实际选择策略的发现收益。

两臂router使用Thompson采样在G/L候选间决策。策略收益随候选耗尽和模型反馈变化，因此V7.2建议开发时使用折扣计数；不声称它在50步内必然最优。

没有合法Local候选时只用Global。两者提同一点只执行一次。无法判定执行的分类标签保持未知，但本次确认失效发现收益为0。角向pass证据只降低Local优先级，不永久删除该方向上的候选。

## V3.1 新增条款五：八族的准入仍按能力和物理语义判断

- S05/S09：先核验ego是否具有实际自主换道/恢复动作能力；仅脚本车辆变化不代表测试意图成立。
- S02：停车几何先核验；名义TTC不冒充实测ego TTC或视觉遮挡证据。
- S04/S09：功能事件单列诊断，不因只看碰撞就声称完整功能正确。
- 几何非法、无参数作用路径等问题在开发阶段修；不能按本文算法输赢排除场景。
- 有效ego碰撞可能发生在计划事件结束前，应计failure，不要求撞车后完成整段事件。
- 零failure家族与历史支持不足的家族不删除；UNKNOWN数量和原因必须报告。
- S07及其后待实现家族继续保留原状态，不因B增加就扩大正式任务。
- IA/IB的历史仅保留追溯，不混入新的V3主结果；附件退役声明与本地执行注册表需一并核验。
